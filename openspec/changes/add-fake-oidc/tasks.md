## 3. The contract suite

- [ ] 3.1 Write `test/support/fake-oidc/fake-oidc.test.ts` first (imports only from `./index.ts`: the ten checks of "All checks pass on the fake" run with `registerRedirect` and `credentials` built from `passwordOf("alice")` and `clientSecret("ursitoare-engine")`, one `test(check.name, check.run)` each; "A broken provider fails" with a `node:http` stub; "Unreachable provider" against a closed port; and "Redaction" after a full sign-in, exchange, userinfo and logout), then implement `oidcContract` in `test/support/fake-oidc/contract.ts` (the only task that changes it) following "Contract checks" below and design.md decision 14, implementing requirements "The contract suite runs against any base URL" and "Secrets are per start and never recorded"

  **Contract checks** (what `oidcContract` sends and asserts; `add-stack-conformance` runs them against Keycloak). Every check uses its own cookie jar (an SSO cookie from another check cannot skip the form), `fetch` with `redirect: "manual"`, a random verifier, state and nonce, and `node:assert/strict`. A *sign-in* GETs `authorization_endpoint` (from discovery) with `response_type=code`, `client_id`, `redirect_uri` = `credentials.redirectUri`, `scope=openid profile email organization`, `state`, `nonce`, `code_challenge` (S256) and `code_challenge_method=S256`, reads the form `action`, POSTs `username` and `password`, and takes `code` from `Location`, which must start with `credentials.redirectUri` and carry `state` unchanged. An *exchange* POSTs `token_endpoint` with `Authorization: Basic base64(clientId:clientSecret)` and form `grant_type=authorization_code`, `code`, `redirect_uri`, `code_verifier`.

  1. `discovery document`: GET `{baseUrl}/.well-known/openid-configuration` is 200; `issuer` equals `baseUrl`; the five endpoints equal `baseUrl` + `/protocol/openid-connect/` + `auth`, `token`, `userinfo`, `logout`, `certs`; `includes` (never equality): `grant_types_supported` has `authorization_code`, `id_token_signing_alg_values_supported` has `RS256`, `code_challenge_methods_supported` has `S256`, `token_endpoint_auth_methods_supported` has `client_secret_basic`, `scopes_supported` has `openid`.
  2. `jwks keys`: GET `jwks_uri` is 200; `keys` holds at least one key with `alg` `RS256` and non-empty `kid`, `n` and `e`.
  3. `code flow with PKCE`: sign-in, exchange: 200, `token_type` equal to `bearer` ignoring case, `access_token` and `id_token` non-empty strings, `expires_in` a positive number.
  4. `claims of the id token`: sign-in, exchange, `decodeJwt` of `id_token`: `iss` equals `baseUrl`; `aud` equals or contains `clientId`; `nonce` equals the sent one; `0 < exp - iat <= 3600`; `organization` deep-equal `[credentials.organization]`; each name of `credentials.groups` is in `groups` and none starts with `/`.
  5. `userinfo with the access token`: sign-in, exchange; GET `userinfo_endpoint` with `Authorization: Bearer {access_token}` is 200 with `sub` equal to the ID token's `sub`; GET with no `Authorization` header is 401.
  6. `wrong password shows the error`: GET the form, POST `username` and `"wrong-" + password`: status 200, no `Location` header, the body contains `Invalid username or password` and `type="password"`.
  7. `plain PKCE is refused`: the authorization GET with `code_challenge_method=plain` and `code_challenge` = the verifier answers 302 whose `Location` has `error=`, or a 4xx; the body has no `type="password"`.
  8. `code is single use`: sign-in, then two exchanges of that code: 200, then 400 with JSON `error` `invalid_grant`.
  9. `redirect uri must match exactly`: the authorization GET with `redirect_uri=https://evil.example/cb` answers 400 to 499, no `Location` header, no `type="password"` in the body.
  10. `logout ends the session`: sign-in, exchange; GET `end_session_endpoint` with `id_token_hint` = `id_token`, `post_logout_redirect_uri` = `credentials.redirectUri`, `state` random: 302 with `Location` starting with that URI and carrying `state`; then userinfo with the `access_token` is 401.

  A `fetch` rejection becomes `FAKE_OIDC_CONTRACT_UNREACHABLE` (cause kept); a failed assertion stays an `AssertionError`. Assertions rest on OpenID Connect Core and RFC 6749, 6750 and 7636, except the error text in check 6 and the refusal of plain PKCE in check 7, which need the realm to pin S256 (a hand-off to `add-keycloak-realm`).
