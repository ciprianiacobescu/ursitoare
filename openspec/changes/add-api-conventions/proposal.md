## Why

Every later endpoint needs the same four answers, and each unit would otherwise invent its own: which error codes the API may return, how a client pages through a list, how a client retries a create without creating twice, and where the API is described. A web page could also be added at a path an API route owns.

Observable result: `ERROR_CODES` lists the 16 codes the API answers, and a test fails when `src` throws `new ApiError(` with a literal code that is not listed or a route declares one that is not. A list endpoint takes `limit` (1 to 200, default 50, else 400 `VALIDATION_FAILED`) and `cursor` and answers `{ items, next_cursor }`; the cursor is opaque, signed with a key derived from the engine key and bound to the tenant and the list, so an edited or foreign one is 400 `CURSOR_INVALID`. A create with `Idempotency-Key` runs once per tenant, principal and key for 24 hours: a repeat gets the stored status and body with `Idempotent-Replayed: true`, the same key with another request is 422 `IDEMPOTENCY_KEY_REUSED`, a repeat while the first runs is 409 `IDEMPOTENCY_IN_PROGRESS`, and a failed attempt can be retried. `GET /api/v1/openapi.json` serves an OpenAPI 3.1 document generated from the route definitions, and a test fails when the committed `docs/api/openapi.json` differs from it. A test fails when a web feature path equals or starts with a reserved root such as `/api` or `/health`.

## What Changes

- `src/api`: the error-code registry, the cursor codec, the page query and envelope, the idempotency functions and the OpenAPI builder and route (files under Interfaces given).
- Migration `0140_idempotency.sql`: table `ursitoare.idempotency_key`, tenant-leading, forced RLS.
- Architecture rules `test/arch/error-codes.ts` and `test/arch/web-routes.ts`; `test/support/openapi-docs.ts` (served text and regeneration script); `docs/api/openapi.json`.
- `src/main.ts` registers the OpenAPI route; the existing test `src/main.api.test.ts::The real engine` gains that route.
