## Purpose

Code hooks wrap node visits in a durable run: placed in onion order, run in the sandbox inside the node's steps or as steps of their own, under a fixed action matrix.

## ADDED Requirements

### Requirement: Hook runners are registered once per kind
`registerHookRunner(kind, runner)` SHALL register one runner per kind `"code"` or `"block"` and refuse another kind or a runner without `run` with `HOOK_RUNNER_INVALID`, a second runner for a kind with `HOOK_RUNNER_DUPLICATE`; `hookRunnerFor` SHALL answer the runner or `undefined`; the nine `HOOK_*` codes SHALL be in both `InterpreterErrorCode` and `INTERPRETER_ERROR_CODES`.

#### Scenario: Registry rules and replayed errors
- **WHEN** after `registerHookRunner("code", codeHookRunner)` (no `index.ts` import), `hookRunnerFor("code")` and `hookRunnerFor("mystery")` run; `registerHookRunner` runs again with `("code", codeHookRunner)`, `("llm", codeHookRunner)`, `("code", {})` and `("block", {})` (casts); and for each of `HOOK_FAILED`, `HOOK_ERROR`, `HOOK_ACTION_INVALID`, `HOOK_ACTION_FORBIDDEN`, `HOOK_ROUTE_UNDECLARED`, `HOOK_RETRY_EXHAUSTED`, `HOOK_UNSUPPORTED`, `HOOK_RUNNER_DUPLICATE`, `HOOK_RUNNER_INVALID`, `toInterpreterError(Object.assign(new Error("m"), { code }))` runs
- **THEN** the first answer is `codeHookRunner` (`===`), the second `undefined`; the registrations throw `HOOK_RUNNER_DUPLICATE` (`details.kind` `code`), then `HOOK_RUNNER_INVALID` (`llm`, `code`, `block`); each of the nine copies converts to an `InterpreterError` with its own code

### Requirement: Step names, fusion, normalisation and the action matrix are pure and fixed
`hookStepName` SHALL return `<node>:<phase>:<label>`, `hookSlot` a placement's 1-based position by identity in `[...pre, ...post]` (`HOOK_ERROR`, `details.reason` `slot_missing`, for any other), `attemptStepName` the name for attempt 1 and `<name>:r<attempt>` later, `isFusable` SHALL hold exactly for a `code` hook without `routes` and `max_retries`, `splitFused` SHALL split off the longest fusable suffix of `pre` and prefix of `post`, `normalizeHookReturn` SHALL turn a return into a `HookOutcome` or throw `HOOK_ACTION_INVALID`, and `checkHookAction` SHALL follow ADR-16 item 5.

#### Scenario: Vectors of the pure functions
- **WHEN** `hookStepName` runs for `("pay", pre, "rule.rule_a")` and `("send", post, "fix_subject")`, each also armed as `after:<name>` by `createFaultPoints`; `attemptStepName` for `("send", 1)`, `("send#done", 2)`, `("pay:post:rule.rule_a", 3)`; `isFusable` for a plain code hook, one with `routes: ["x"]`, with `routes: []`, with `max_retries: 1`, and a block hook; `splitFused` for `pre` `[F,F,F]`, `[N,F,N,F]`, `[F,F,N]`, `post` `[F,N,F]`, `[N,F]` (F fusable, N not) and two empty lists; `hookSlot` for the six `hookPlacements` of `onion`'s `pay` and one of `lookup`; `normalizeHookReturn` and `checkHookAction` for the rows of `test-plan.md` § Normalisation and § Action matrix
- **THEN** the names are `pay:pre:rule.rule_a`, `send:post:fix_subject` (both arm without error), `send`, `send#done:r2`, `pay:post:rule.rule_a:r3`; `isFusable` gives `true, false, false, false, false`; (`ownPre`/`fusedPre`) are `[]`/`[F,F,F]`, `[N,F,N]`/`[F]`, `[F,F,N]`/`[]`, (`fusedPost`/`ownPost`) `[F]`/`[N,F]`, `[]`/`[N,F]`, and the empty lists give four empty arrays; `hookSlot` gives `1` to `6` in order and throws `HOOK_ERROR` (`details` `{ reason: "slot_missing" }`) for the `lookup` one; each table row gives its outcome, `details` or verdict

### Requirement: Built-in runtimes hand their input and output to the hooks
When `services.hooks` is set, each of `block`, `code`, `switch`, `end` and `wait` SHALL call `hooks.pre(input)` inside its first step after resolving its input, run on the input returned (`end`: use it as its output), do no work on `skip`, call `hooks.post({ output, outcome, next })` inside its last step (`<id>`; `<id>#done`; `<id>#wake`) and use the output returned; a block's `ToolCall` SHALL carry `generation: ctx.attempt - 1` only above attempt 1; without `services.hooks` nothing changes.

#### Scenario: The protocol of each runtime
- **WHEN** each runtime runs with a recording `NodeHooks` (`post` answers `{ output }`; `pre` answers `run` of its input unless stated; `run X` is `{ action: "run", input: X }`): `lookup` (read block) with `pre` answering `run { vendor_name: "Acme2" }` and `post` `{ vendor_id: "v9", status: "active" }`, with `pre` answering `run { vendor: 1 }`, and with `{ action: "skip", output: S }`; `pay` (effect block) with `pre` answering `run` of its args plus `currency: "USD"`, at `ctx.attempt` 1 and 2; `normalize` (code, recording sandbox) with `pre` answering `run { amount: 5 }` and `{ action: "skip", output: S }`; `gate` (switch on `${{ inputs.mode }}`, cases `{ a: "x" }`, default `y`, mode `a`) with `pre` answering `run { on: "b" }` and `run {}`; `w` (wait `PT1H`) in `mock` and `live` mode, `pre` answering `run { duration: "PT2H" }`; the end of `onion` and an end with no output
- **THEN** `lookup`: `pre` got `{ vendor_name: "Acme" }`, the invoker `{ vendor_name: "Acme2" }`, `post` `{ output: LOOKUP_OK, outcome: null, next: <node.next> }`; `run { vendor: 1 }` throws `INTERPRETER_INPUT_INVALID` (`path` `/`, `keyword` `required`), no invoker call; `skip`: no invoker call, `post` gets `output: S`, `S` is the output; `pay`: steps `pay`, `pay#done`, `pre` inside `pay` before `effects.before`, `before` and `after` get equal args with `currency: "USD"`, `post` inside `pay#done` after `after`, the call has no `generation` key at attempt 1 and `generation: 1` at attempt 2; `normalize`: sandbox input `{ amount: 5 }`, no call on `skip`; `gate`: `pre` got `{ on: "a" }`, `run { on: "b" }` gives outcome `default`, `next` `y`, `run {}` throws `INTERPRETER_INPUT_INVALID` (`path` `/on`, `keyword` `required`); `w`: `pre` got `{ duration: "PT1H" }`, `mock` never sleeps and `post` in `w#wake` gets `outcome: "skipped"`, `live` sleeps 7,200,000 ms; the ends: `pre` got `{ payment_id: "pay-1" }` and `null`, the `input` of its `run` answer is the output

### Requirement: Hooks run in onion order, fused at the edges of each chain
`visitNode` SHALL place a node's hooks with `hookPlacements`, run those whose `when` matches in that order, the fusable suffix of the pre chain and prefix of the post chain inside the node's steps and the rest as steps named `attemptStepName(hookStepName(node, placement), attempt)` (value: the `HookRun`), give every runner the site `slot` `hookSlot({ pre, post }, placement)`, pass each `HookRun.entry` to `deps.hookObserver` in order, and record each step of a node with a fused placement as `{ value, __fused }`, others as in M4.

#### Scenario: The onion flow, all fused, and with one own step
- **WHEN** every flow of `hookRunNames()` (the nine § Fixtures files, never `loadHookFlow`'s `0.2-draft` flows, D3) and the variant `onion-own` go through `validateFlowText(text, "yaml", loadTestCatalogue())`; then `onion` and `onion-own` run with `INPUT`
- **THEN** each flow gives `ok` true, no error or warning, `layers_run` `["L1", "L2", "L3", "H"]`; `onion` completes with `executed` `[LEAD, "lookup", "normalize", "pay", "pay#done", "done", "run:finish"]`, `OBS` equal to `OBS_ONION`, 8 sandbox calls with binding `ctx`, four `completed` rows, an `idemKey` only on `pay`, `done` input `null`; the value of `lookup` is `{ value: LOOKUP_OK, __fused: <two records> }`, that of `normalize` is plain; `onion-own` differs only in a step `pay:post:rule.rule_a` after `pay#done` (value a `HookRun`) and an `OBS` entry without `*`

### Requirement: A pre-hook changes the input or skips the node, and the row shows the effective input
A pre-hook `continue` with `input` SHALL replace the input the node runs on, a pre-hook `skip` the work of a read block or `code` node with its object output, a post-hook output the node's output (schema-checked); the row SHALL carry the effective input (state `skipped` and the skip output after a skip); for `end` the hook-visible input SHALL be the resolved `output` map and the effective input the run's output.

#### Scenario: Mutate, skip and end
- **WHEN** `mutate`, `bad-upper`, `skip-read`, `skip-pay` and `end-pre` each run with `INPUT`
- **THEN** `mutate` completes, the lookup invoker and row input are `{ vendor_name: "Acme" }`, the `normalize` row output is `{ amount: 120, currency: "EUR" }`, the `pay` args hold `currency: "EUR"`; `bad-upper` fails `INTERPRETER_OUTPUT_INVALID` at `normalize` (`details` `{ path: "/amount", keyword: "type", hook: "normalize:post:upper_currency" }`), its row `failed`, `pay` not called; `skip-read` completes with no lookup call, row `lookup` `skipped` (output `{ vendor_id: "v-cached", status: "active" }`, input `{ vendor_name: "  Acme " }`), `pay` args holding `v-cached`; `skip-pay` fails `HOOK_ACTION_FORBIDDEN` (`details` `{ hook: "pay:pre:fake_payment", action: "skip" }`) at `pay`, row `failed`, no `before` call; `end-pre` completes with output digest `payloadDigest({ payment_id: "pay-1", paid: true })`, the `done` row input and output being that map

### Requirement: Hooks see the context, redirect within their routes and fail the node
A hook SHALL run only when `whenMatches` allows and receive a `HookContext`: the metas of the node, of the node visited before (`null` at `start`), of its successor (before the node's step the sole static successor of a `block`, `code` or `wait`, else `null`; after it the current) and of `augmentedSuccessors`, the effective input, current output and outcome, the attempt, the feedback and the resolved hook `input` as `args` (in a post-hook the wrapped node counts as available); a `redirect` SHALL change the successor for later hooks and the run, one outside the hook's `routes` SHALL fail `HOOK_ROUTE_UNDECLARED`, one to a node of effect `write`, `send`, `pay` or `null` `HOOK_ACTION_FORBIDDEN`, and `fail` SHALL fail the node `HOOK_FAILED`.

#### Scenario: Context, when, redirect, undeclared route and fail
- **WHEN** `redirect` runs with `{ vendor: "Acme", amount: 2000, mode: "auto" }` over a recording `SB`, and with amount 20; `undeclared` and `F8` run with amount 20; `fail` runs with `INPUT`, and with the lookup answering `{ vendor_id: "v2", status: "blocked" }`
- **THEN** at 2000 it completes with `executed` `[LEAD, "gate", "classify", "classify:post:to_review", "classify:post:after_redirect", "review", "done", "run:finish"]`, `OBS` `gate/post:saw_default*`, `classify/pre:pre_look*`, `classify/post:to_review`, `classify/post:after_redirect`, rows `gate`, `classify`, `review`, `done`, no `pay` call; the four contexts, as (`phase`, `node`, `from`, `next`, ids of `next_candidates`, `input`, `output`, `outcome`, `args`), are (`post`, `M_gate`, `null`, `M_classify`, `[review, classify]`, `{ on: "auto" }`, `null`, `"default"`, `{}`), (`pre`, `M_classify`, `M_gate`, `M_pay`, `[pay, review]`, `{ amount: 2000 }`, `null`, `null`, `{ v: "Acme" }`), (`post`, `M_classify`, `M_gate`, `M_pay`, `[pay, review]`, `{ amount: 2000 }`, `{ risk: "high" }`, `null`, `{ limit: 1000 }`) and, for `after_redirect`, the last with `next` `M_review` and `args` `{}`, all with `attempt` 1 and `feedback` `null`; at 20 `pay` runs once, `after_redirect` not; `undeclared` fails `HOOK_ROUTE_UNDECLARED` (`details` `{ hook: "classify:post:to_review", to: "pay" }`), row `classify` `failed`, no `pay` call; `fail` completes, and blocked fails `HOOK_FAILED` (`details` `{ hook: "lookup:post:no_blocked", reason: "vendor blocked" }`) after one lookup call, no `pay` call; `F8` fails as test-plan.md § Variants says, no `pay` call

### Requirement: A post-hook retries a node under its limit, with a new effect key per attempt
A post-hook `retry` SHALL re-run the node as attempt `a + 1` with the retry's `input` when given and its `feedback` in the context, without pre-hooks, name each step of that attempt `attemptStepName(name, a + 1)`, write one row per attempt (attempt `a`, `generation` 0, the next `seq`) and restart the post chain; `a - 1 >= max_retries` SHALL fail `HOOK_RETRY_EXHAUSTED`; an effect call on attempt `a` SHALL use `generation = a - 1`; a post-hook SHALL run only after the node's own work succeeded (a fused one inside the last step, after the tool call and `effects.after`), so a node step that throws SHALL fail the node at once, with no post-hook and no later attempt.

#### Scenario: Retries, keys and no retry after an unknown effect
- **WHEN** (versions as `test-plan.md` § Runnable versions) `f-ret` and `f-ret-exhausted` run with `{ query: "q" }`; `f-eff` runs with `{}`, and again with the gate answering `unknown` on its first call

### Requirement: Hooks never remove a taint label
A node's `started` row SHALL carry `nodeInputTaint` (the base input taint); the final row of each attempt SHALL carry the effective input taint: `nodeInputTaint` joined with the taint `H` of each pre-hook that changed the input or skipped and of the hook whose retry began the attempt (`H`: the effective input taint so far, `valueTaint` of the hook's `input` and, in a post-hook, every produced output and field label); produced taint SHALL be `producedTaint(node, effective input taint, catalogue)`, for a skipped node joined with that taint (X2), and, when a post-hook changed the output, the output and each field label joined with that hook's `H`.

#### Scenario: Taint rows through hooks
- **WHEN** `taint-hook` runs with `{ invoice: "inv-1" }` over `SB` and a recording store, and so does a copy whose `sanitise` has no `input`
- **THEN** the `taint` of rows `fetch`, `use_id`, `done` is `[]`, `["untrusted"]` (`sanitise` changed the output, its args hold `raw_text`) and `["untrusted"]` (`tag` changed the input and its args hold `raw_text`); the `started` write of `done` has `taint` `[]`; in the copy `use_id` is still `["untrusted"]` (`fetch`'s produced labels join, so a hook cannot launder them)

### Requirement: A hook fault fails the node and never leaves a run running
A node with a hook of a kind without runner SHALL fail `HOOK_UNSUPPORTED`, one with a code hook and no sandbox `INTERPRETER_NO_SANDBOX`, both before the first step, with no row; a sandbox fault SHALL fail the node `HOOK_ERROR` (`details.fault`), a `WorkerSandbox.run` that rejects SHALL fail the node `HOOK_ERROR` with `details` `{ hook, fault: "sandbox_unavailable" }` inside the hook's step (the node's step when the hook is fused) and the run `failed`, with no rejection text in a message, row or log, a return outside the action grammar `HOOK_ACTION_INVALID`, an `input`, `output` or `feedback` that is not a storable payload `HOOK_ACTION_INVALID` with `details.keyword` `payload` inside the hook's step (the node's when fused), a skip or mutated output outside the output schema `INTERPRETER_OUTPUT_INVALID` with `details.hook`, an unresolved input reference `INTERPRETER_REF_UNRESOLVED` before any hook runs; no message SHALL hold hook text.

### Requirement: Hook code obeys the sandbox suite
`runCodeHook` SHALL run a hook on the injected `WorkerSandbox` with `HOOK_LIMITS` (equal to `DEFAULT_SANDBOX_LIMITS`), seed `<runId>:<node>:<phase>:<label>:<attempt>`, `nowIso` of the step's `now`, binding `ctx` and result `object_or_null`, and every `ESCAPE_CASES` case SHALL pass under them.

#### Scenario: The escape suite on hook code
- **WHEN** `runCodeHook` runs once over a recording `SB` (node `esc`, hook `esc`, attempt 1); then each of the 42 `ESCAPE_CASES` runs through `LIM` (§ Escape sweep) and `checkEscapeCase(c, r, "hook")`
- **THEN** the recorded call has `limits` equal to `DEFAULT_SANDBOX_LIMITS` and `options` `{ seed: "r_1:esc:pre:esc:1", nowIso: "2026-11-02T10:00:00.000Z", binding: "ctx", result: "object_or_null" }`, `HOOK_LIMITS` equals `DEFAULT_SANDBOX_LIMITS` and is frozen, and each `checkEscapeCase` returns `null`

### Requirement: A replay runs no recorded hook and reaches the same rows
A replay over a prefix of the recorded step values SHALL run only the later steps, restore a fused node's input, output, taint and entries from its records, run no recorded own-step hook, and leave rows equal to the first run's, `idemKey` included.
