## Context

After U15c the stylesheet entry layers the kit under Tailwind utilities, and after U15d the kit styles tables as cards, bounds `.ui-field` at 40 rem and paints `data-tone` buttons. U21b moves seven pages onto those parts: markup, class names, two kinds of data (names, badges). Logic files stay as they are, so every row string, native select, dialog text and `aria-disabled` control is the one the frozen tests pin. Rulings D8, D9, D24 and the U15d Q5 ruling apply.

Names restated from the in-plan units (a dependent's judge sees those folders cut at 30,000 characters):

- U15d `web/src/kit/layout/layout.ts`: `captionDisplayFor(caption: string, heading: string): "visible" | "hidden"` is `"hidden"` iff both trimmed strings are equal (case-sensitive); `PAGE_WIDTHS: Readonly<{ form: "max-w-3xl"; list: "max-w-6xl"; wide: "max-w-none" }>`. `DataTableProps` gains `captionDisplay?: "visible" | "hidden"`; hidden writes the class `ui-table-caption ui-visually-hidden` on the `<caption>` and the table keeps its name. `PageHeaderProps` is `{ title: string; description?: string; meta?: ReactNode; actions?: ReactNode; headingRef?: Ref<HTMLHeadingElement> }`; it renders `<div className="ui-page-header">` with `<h1 tabIndex={-1} ref={headingRef}>` whose text is exactly `title`, and no landmark, role, link, `status` or `alert`. `SectionProps` is `{ title: string; headingLevel?: 2 | 3; actions?: ReactNode; className?: string; id?: string; children?: ReactNode }`; it renders a `region` named `title` (an `h2` by default) with the classes `cn("ui-section", className)`, and `.ui-section` is itself a bordered, padded card. U15d's `theme.css` paints `.ui-button[data-tone="primary"]` accent and `[data-tone="danger"]` red; its `ConfirmDialog` writes `data-tone="danger"` on the confirm button when `destructive` is true, else `"primary"`.
- U15c: `Card(props: ComponentProps<"div">)` is `<div data-slot="card">`; `Badge(props: { tone: Tone; children: ReactNode; className?: string })` is `<span data-slot="badge" data-tone>`; `cn(...inputs: ClassValue[]): string`; `serverStateTone` maps `pending` and `drifted` to `warning`, `approved` to `success`; `grantStatusTone` maps `active` to `success`, `needs_reconfirm` to `warning`, `revoked` and anything else to `neutral`. Token utilities such as `text-text-muted` exist; the palette is off.
- U18b: `useDisplayNames(userIds: readonly string[]): ReadonlyMap<string, string>` is empty until resolved and never throws; `personLabel(names: ReadonlyMap<string, string>, userId: string): string` is the trimmed name, else `userId`. The cache asks `GET /people?ids=` only for ids that match `^[A-Za-z0-9_-]{1,64}$` and were not asked before; a failed batch resolves without names.

## Decisions

1. **U15d's tests tolerate this unit (coordinator ruling).** U15d's `e2e/test_m6b_kit.py` runs against `/admin/users`, and a fixed-value form of two of its tests would fail here: the caption class (D9 hides the Users caption: `ui-table-caption ui-visually-hidden`) and the Disable confirm colour (Q5: `destructive`, `rgb(180, 35, 24)`). U15d rewrites those two tests to check relations: the caption's class list contains `ui-table-caption`, and the confirm's background equals the token for its own `data-tone`. They then hold under this unit, which edits no test of U15d's. On the scratch build, with the fixed-value form, those two were the only e2e failures (80 of 82).
2. **Destructive confirms.** Every `ConfirmDialog` on the seven pages:

   | Page, line on main | Confirm text | `destructive` | Confirm tone |
   |---|---|---|---|
   | Users `UsersPage.tsx:140` | "Disable user" | added by this unit | danger, `rgb(180, 35, 24)` |
   | Roles and teams `TeamsPage.tsx:202` | "Delete team" | already (`:207`) | danger |
   | Group mappings `MappingsPage.tsx:304` | "Remove mapping" | already (`:309`) | danger |
   | Tool servers `ServersPage.tsx:258` | "Approve surface" | no (an approval) | primary, `rgb(29, 78, 216)` |

   `destructive` also moves the first focus to "Cancel" (`confirm.ts:76`); the dialog's name, texts and the `h1` focus after it are unchanged, and m2:114-118 click the button by name. **Revoke grant has no `ConfirmDialog` on main** (`GrantsPage.tsx:153-168` revokes on the click) and gets none: tp:535-551 click "Revoke", count the requests and assert zero dialogs (:551). Row buttons (Disable, Enable, Delete, Remove, Revoke) stay quiet; only a dialog's confirm is toned.
3. **Names (D8).** A name replaces an id in two places, through `useDisplayNames` and `personLabel`: the Group mappings "Reviewed by" cell, `clip(personLabel(names, mapping.reviewedBy))` (the seeded mapping's `reviewedBy` is `operator:e2e-seed`, no user id, so it is never asked and shows as is), and a new line `<p className="text-text-muted">Registered by {personLabel(names, view.registeredBy)}</p>` between the servers table and the region "Surface", outside it because that region's text is pinned. These stay ids, and no test asks for names there: grant subjects (`user u_bob`, tp:503-547), audit actors (`user: u_carol`), run, decision and service ids, digests and server ids. `createdBy`, `revokedBy`, `pendingSubmittedBy` and `deployedBy` are not rendered. Users, Roles and teams, Audit, Grants and Policies import nothing from `web/src/people/`, so they send no `/people` request.
4. **Captions (D9).** Each page calls `captionDisplayFor(<spec>.caption, <its h1 text>)`: Users, Group mappings, Tool servers and Grants give `hidden`; "Roles" and "Teams" (page "Roles and teams"), "Audit events" (page "Audit log") and "Tools" (page "Tool servers") stay visible. The table keeps its accessible name.
5. **Badges.** A state is a `Badge` around the trailing state word, so a composed row string keeps its `textContent`: the Tool servers list cell and the Surface line are `serverRowText(row)` with its last `row.state.length` characters in `<Badge tone={serverStateTone(row.state)}>`, the grant `span` is `grantRowText(grant)` with `grant.status` in `<Badge tone={grantStatusTone(grant.status)}>`; text that does not end with the state is rendered plain. The Users state cell is `<Badge tone="success">Active</Badge>` or `<Badge tone="neutral">Disabled</Badge>` (no account mapper exists; the choice is one line in `UsersPage.tsx`). Badges are `span`s with no role, so no `status` is added; pins g:83, tp:293, :362, :386 and tp:503-547 hold.
6. **Page frame.** Each root is `cn("admin-page", PAGE_WIDTHS.list)` (tools: `tools-page`), except Policies, `PAGE_WIDTHS.form` (deviation from the card: one editor is better at 48 rem). `admin.css` and `tools.css` lose `max-width: 64rem` (the utility would win, and a dead rule would mislead). The `h1` is `PageHeader`'s, with `headingRef={headingRef}` on the admin pages (m2:118, :128 focus it). One `h1` per page; `Section` titles are the existing `h2` texts "Create team", "Map a group", "Chain verification", "Filter the audit log", "Surface" and "New grant", none a label of a control (`get_by_label("Tool", exact=True)` stays unique). Descriptions, free text that no test matches: Users "Everyone who has signed in, with their roles and teams."; Roles and teams "Roles are fixed. Teams group people, and a group mapping can give a team to everyone in an identity-provider group."; Group mappings "Give people a role or a team when they sign in through an identity-provider group."; Audit log "Every recorded action, with a check that the chain of events is unbroken."; Tool servers "Servers whose tools flows can call. ## Failure cases and security

- `/people` answers 500 or an unreadable body: names stay empty, "Reviewed by" shows the id and "Registered by" shows `u_carol` (one request, no retry loop). A `reviewedBy` or `registeredBy` that is not a user id (`operator:e2e-seed`, `e2e-seed`) is not requested and shown as is. An unknown state gives a neutral badge with the same text. A failing or empty list shows the kit's `ErrorPanel` or `EmptyState`; Grants with both reads failing keeps exactly 2 `alert`s (tp:452) and the one option "Choose a tool".
- No endpoint, action, secret, package or CSP change; no `style=`, `<style>`, `dangerouslySetInnerHTML` or colour word in a class name. A display name is rendered as text; `/people` is read-only and returns `userId`, `displayName`, `kind` only (U18b).
