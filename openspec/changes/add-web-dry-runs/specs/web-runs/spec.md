## Purpose

The editor starts attended dry runs, the run page shows each policy decision with its permit and the stubbed effects, every step shows its taint, and the M6 journeys prove the milestone.

## ADDED Requirements

### Requirement: The Dry run panel follows the capability and the saved version
`dryRunPanelView(capabilities, version)` SHALL give `{ state: "not_allowed", message: "Only members of the flow's owner team can dry-run it." }` without `dry_run_flow`, otherwise `{ state: "needs_version", message: "Save and validate a version to dry-run it." }` for no version or a `draft`, otherwise `{ state: "ready", message: null }`. `DRY_RUN_PANEL` SHALL be `{ id: "dry-run", title: "Dry run" }` and `web/src/features/80-runs.tsx` SHALL register it beside the Test run panel, so the editor shows a region "Dry run" (`h2`) that holds the message for `not_allowed` and for `needs_version`, and for `ready` the paragraph "Read steps call the real tools through the broker. Write, send and pay steps are checked by policy but answered by your fakes, one list per step." with the example `{"pay": [{"output": {"payment_id": "P-1", "status": "created"}}]}` in a `code` element, and then the form "Dry run inputs" with the fields "Input (JSON)" and "Fakes (JSON)" (both starting `{}`) and the button "Start dry run".

#### Scenario: Not allowed, needs a version, ready

### Requirement: The fakes text becomes a map of lists or a message
`parseFakes(text)` SHALL trim the text and answer `{ ok: false, message }` with "Enter a JSON object." for empty text, "This is not valid JSON." for text that does not parse, "Enter a JSON object, for example {}." for JSON that is not a plain object, and `The fakes for "<key>" must be a list.` for the first key (in key order) whose value is not an array; otherwise `{ ok: true, fakes }` with every list copied and every key an own property of an object whose prototype is `Object.prototype` (a key `__proto__` stays a key). It SHALL NOT judge list entries: the engine's `checkFakes` does.

### Requirement: A dry run is started with one exact request, and each refusal is worded for the form
`startDryRun(api, flowId, hash, input, fakes, key)` SHALL throw `RangeError` before any request for a `flowId` outside `^[a-z][a-z0-9]*(-[a-z0-9]+)*$` (at most 64 characters), a `hash` outside `^sha256:[0-9a-f]{64}$` or an empty `key`; otherwise it SHALL call `api.post` once with the path `/flows/<flowId>/versions/<encodeURIComponent(hash)>/dry-run`, the body `{ input, fakes }` and the options `{ headers: { "Idempotency-Key": key } }`, and return `parseRunView` of the answer's `run`, or throw `ApiRequestError` 200 `INVALID_RESPONSE` "Invalid dry run answer" when it is unreadable. `dryRunFormErrors(error)` SHALL map a 400 `VALIDATION_FAILED` with `details.fields`: a field `body/fakes` or `body/fakes/<key>[/<index>]` to the form field `fakes` with the parts `<key[/index]>: <message>` (the bare message for `body/fakes`) joined by `; `, at most three; the first field under `body/input` to `input`; any other field to the `$form` text; and every other error as `testRunFormErrors` does.

### Requirement: Policy decisions are parsed strictly and read as permits
`parseDecisions(raw)` SHALL take the `items` of one page of `GET /api/v1/runs/{runId}/decisions` and return `DecisionViewWeb[]` (members `decisionId`, `nodeId`, `resource`, `decision`, `reasons`, `permit`; every other member ignored), or `null` when `raw` is not an array or an item lacks a `decisionId` matching `^[A-Za-z0-9_.:-]{1,128}$`, a `nodeId` null or of 1 to 256 characters, a `resource` of 1 to 512 characters, a `decision` of `allow` or `deny`, at most 64 `reasons` of 1 to 256 characters, or a `permit` that is null or has a `method` matching `^[A-Z]{3,10}$`, a `host` matching `^[a-z0-9.-]{1,253}(:[0-9]{1,5})?$`, a `path` matching `^/[\x21-\x7e]{0,2047}$`, a `serviceId` matching `^[A-Za-z0-9._:-]{1,128}$` and an integer `ttlSeconds` from 1 to 3600. It SHALL also give `null` when any string it keeps (`decisionId`, `nodeId`, `resource`, every reason and the permit's `method`, `host`, `path` and `serviceId`) holds a C0 or C1 control character, U+0000 to U+001F or U+007F to U+009F; one such item makes the page unreadable, like any other malformed item. `permitText(p)` SHALL be `${method} ${host}${path}`.

### Requirement: Each decision is one row that names its node, outcome and permit, and says when the effect was stubbed
`decisionRows(run, steps, decisions)` SHALL give one row per decision, in order. The row's `nodeId` is the part of `resource` (`Block::"<tenant>/<flow>/<rest>"`, at least three non-empty segments) after the second `/`, else the decision's `nodeId`, else `(unknown)`; its `text` joins with ` · ` that label, the decision, `stubbed` and `permitText(permit)`, the last two only when they apply. `stubbed` applies when `run.mode` is `stub`, the decision is `allow`, and the last step (highest `seq`) of the decision's `nodeId` is of kind `block` and, for a node decision (label equal to `nodeId`), has `idemKey` not null, or, for a hook decision (label `<nodeId>:<phase>:<hook>`), has a `hooks` entry labelled `<phase>:<hook>` with `idemKey` not null. Its `details` are `Decision id`, `Resource`, `Reasons` (joined by `, `; with no reason `none` for an allow and `No grant or policy allows this call.` for a deny), then `Service` and `Token lifetime` (`<n> s`) when there is a permit.

### Requirement: The run page lists the decisions of a finished stub run and confines their failure
`decisionsWanted(run)` SHALL be true only for a run whose mode is not `mock` and whose state is `completed`, `failed` or `cancelled`. `loadDecisions(client, runId, signal)` SHALL throw `RangeError` for a run id outside `^[A-Za-z0-9_-]{1,128}$`, read `/runs/<runId>/decisions` with `limit` 100 and the previous `next_cursor` for at most 5 pages, and return `{ decisions, truncated }` (`truncated` when the fifth page still had a cursor), or throw `ApiRequestError` 200 `INVALID_RESPONSE` "Invalid decisions" for an unreadable page. `decisionsView(run, steps, load)` SHALL answer `hidden` when `decisionsWanted` is false, `loading` for no load or a loading one, `error` with the kit's text for an `ApiRequestError` other than `INVALID_RESPONSE` and otherwise "Policy decisions could not be read.", `empty` with "No policy decisions were recorded.", else the rows and, when truncated, the note "Showing the first 500 decisions.". `RunPage` SHALL load the decisions once the run is terminal (and again on "Try again") and show, unless `hidden`, a region "Policy decisions" (`h2`) holding a loading state, a paragraph (not an alert) or a list named "Policy decisions" with one item per row (its `text`, then a `dl` of its details); a failed load SHALL NOT change the rest of the page.
