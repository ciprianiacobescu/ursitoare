## Purpose

The graph page and the editor's Graph panel list a flow's node-level hooks and the routes its post hooks declare, and show a flow's rules as text, so a reader sees where a hook may send a run.

## ADDED Requirements

### Requirement: The graph lists hooks, hook routes and flow rules beside the drawing
`hookOverlay(doc, layout)` SHALL read a canonical flow document without changing it and return the `badges` (one per laid-out node with a hook id in `pre` or `post`, in layout order), the `routes` (one per post hook and route that names a laid-out node, without repeats), the `rules` (one per flow rule with a non-empty string id; when the rule's `post` hook declares `routes`, its `post` is `rule.<id> routes <ids joined by ", ">`, so no rule route is hidden) and the `missing` route targets; it SHALL list at most 16 hooks per phase and 16 rules (U41's bounds) and every route (each names a laid-out node), cut an id to 64 characters, and answer four empty lists for a non-flow. `FlowGraphView` SHALL add, only when a list is not empty and after the list "Nodes", an `h3` "Hooks" with a list named "Hooks" (one item per badge), an `h3` "Hook routes" with a list named "Hook routes" (one item per route, `hookRouteText`), and an `h3` "Flow rules" with a list named "Flow rules" (one item per rule) followed by one paragraph saying that rules are listed and not drawn; it SHALL draw each route inside the decorative `svg` as a dashed `path` of class `hook-route` (`hookRoutePaths`: key `${from}>${to}:${hook}`, `d` `M x1 y1 L x2 y2` with `x1`, `x2` each node's `x + GRAPH_GEOMETRY.nodeWidth / 2 + 16`, `y1` the bottom of `from`, `y2` the top of `to`; nothing for a route to its own node or to a node not laid out). It SHALL leave `layoutFlow`, `graphView` and the page of a flow without hooks unchanged.

#### Scenario: Badges, routes, rules and missing targets
- **WHEN** `hookOverlay` runs on `HOOKED`, `X3` and `RULES` of test-plan.md with `L(doc)`, and `hookBadgeText`, `hookRouteText`, `flowRuleText` and `hookRoutePaths` run on their results
- **THEN** `HOOKED` gives `{ badges: [{ nodeId: "pay", pre: ["guard"], post: ["notify"] }], routes: [], rules: [], missing: [] }` and the badge text `pay: pre guard; post notify`; `X3` gives the badge `{ nodeId: "classify", pre: [], post: ["rush"] }` (text `classify: pre none; post rush`), the one route `{ from: "classify", to: "pay", hook: "rush" }` (text `hook rush: classify may route to pay`), and the path `{ key: "classify>pay:rush", d: "M 112 168 L 112 328", className: "hook-route" }`; `RULES` gives the badges, routes, `missing` `["ghost"]` and rules of test-plan.md § Overlay fixtures, with the texts `a: pre none; post tidy, tidy2`, `hook tidy: a may route to a` and `audit: match kind block and effect pay, send; pre rule.audit; post none`, the fixture's entries without a string id and the repeated route `ghost` not listed twice

#### Scenario: Odd documents, limits, no mutation and an unchanged drawing
- **WHEN** `hookOverlay` runs on `null`, on `{ nodes: 5, hooks: "x" }`, on a deeply frozen `RULES`, and on a document whose node `a` has 17 `pre` hooks `h1` to `h17` and whose `hooks` has 17 rules, the first with an id of 70 characters; `hookRoutePaths` runs on `[{ from: "a", to: "a", hook: "t" }, { from: "a", to: "zz", hook: "t" }]` with `L(RULES)`; `layoutFlow` runs on `HOOKED` and on `HOOKED` with every `pre` and `post` removed, and `graphView(HOOKED, true)` and `graphView(X3, true)` run
- **THEN** the first two give `{ badges: [], routes: [], rules: [], missing: [] }`; the frozen input throws nothing and equals its `structuredClone` taken before; the badge of `a` lists `h1` to `h16`, there are 16 rules, and the long id is its first 63 characters plus "…"; `hookRoutePaths` gives `[]` (a route to the same node and a route to an unknown node are not drawn); the two layouts are deep-equal; the messages are "Flow graph: 6 nodes, 5 edges, 5 layers." and "Flow graph: 5 nodes, 4 edges, 5 layers."
