## ADDED Requirements

### Requirement: A surface is read for review with each tool's call, flags and the server's hints
`parseReviewTools(surface)` SHALL return one `ReviewTool` per tool in surface order, or `null` for a surface that design.md decision 3 refuses, with `call`, `hints` and `serverName` (the `mcp` call's `name`, else `null`) as it says. `callRows(tools)` SHALL give each tool's `name`, `call`, `effect`, `retry` (`unsafe to retry` or `safe to retry`), `result` (`untrusted` or `trusted`) and `hints`; `readNote(tools)` SHALL give the sentence of test-plan.md C2 when a tool is `read`, else `null`. A server's hints SHALL never change `effect`, `untrusted_result` or `unsafe_to_retry`.

### Requirement: The drift diff compares the approved and the pending surface by tool name
`surfaceDiff(approved, pending)` SHALL return, sorted by name, `added` for a tool only in `pending`, `removed` for one only in `approved` and `changed` with the differing fields in the order `effect`, `description`, `input`, `output`, `untrusted_result`, `unsafe_to_retry`, `data_class`, `call`, `hints`, `untrusted_fields` (design 4); an unreadable side gives `[]`. An `added` item SHALL carry `description` `{ old: null, new }` and `input`, and a `changed` item whose fields include `description` the `description` `{ old, new }` (the full texts or `null`, D17a), one whose fields include `input` the new side's `input`: `{ property, text }` for each property of `input.properties` with a string `description` (C7). `changeText` SHALL give `added x`, `removed x` or `changed x: effect, call`. `changesView(approved, pending)` SHALL compare an absent approved surface as no tools, so a first approval lists every tool as `added`, and SHALL give `{ text, items }`: the text "No pending surface to compare." for an absent pending surface, "The surface could not be read." for an unreadable one, "No changes." for an empty diff, else `text` null and one item `{ text, lines }` per change, `text` the `changeText` and `lines`: `Description: <text>` for an `added` item, `Description before: <old>` and `Description after: <new>` for a description change, then one `Input <property>: <text>` per `input` entry, at most 50, then `(N more properties)`. Each text is `(none)` for `null`, a line feed shown as `↵`, every other character of category Cc, Cf, Co, Cn, Zl or Zp (`/[\p{Cc}\p{Cf}\p{Co}\p{Cn}\p{Zl}\p{Zp}]/gu`, so the zero-width, bidi, TAG and soft-hyphen characters) as `?`, and shown in full up to 2,000 characters (U53 and U54 bound a description there), else cut with ` (N more characters)`; the admin reads what reaches the agents as plain text (C6, C7). A change of the server's hints alone SHALL read `changed <tool>: hints`.

### Requirement: Effect settings become the overlay body and a discovery answer names every tool left out
`DiscoverDraft` SHALL hold `effects` (`""`, `read`, `write`, `send`, `pay` or `skip` per server tool name) and optional `names`. `initialDraft(tools)` SHALL give each tool with a `serverName` (not `__proto__`) the effect `""` for `write` and its effect otherwise, and a name when its tool name differs from the server's (a tool not in `tools` has no entry, so the body leaves it to the proposal). `discoverBody(draft)` SHALL return `{ tools }` holding `{ effect?, name?, skip? }` per tool: `effect` unless `""` or `skip`, `name` unless empty or skipped, `skip: true` for `skip`, no entry for an empty one and none for `__proto__` (it defaults); every lookup by a server tool name SHALL use `Object.hasOwn`; it SHALL throw `RangeError` for a key outside `^[A-Za-z0-9_.-]{1,128}$`, an effect outside the list, a name outside `^[a-z][a-z0-9_]{0,63}$` and more than 100 entries (C9, m2). `parseDiscovery(raw)` SHALL return `{ protocolVersion, era, count, excluded }` for a `{ server, era, protocolVersion, excluded }` answer, `count` being the length of `server.tools` (at most 100), `era` `modern` or `legacy`, `protocolVersion` one of `2026-07-28`, `2025-11-25`, `2025-06-18`, `2025-03-26`, and `excluded` at most 1,000 entries of a string `name` and a `reason` `^[a-z][a-z0-9_]{0,63}$`; anything else is `null`. `discoveryText(d)` SHALL be `Discovered ${count} tools over MCP ${protocolVersion}.` and, when any tool was left out, ` Left out: ` plus `<name> (<reason>)` joined by `, `, a name neutralised as the descriptions are (C6) and cut to 79 characters and `…` when over 80; an entry with reason `description` reads `<name> (description dropped, tool kept)`, since U54 keeps that tool.

### Requirement: The discovery call and the review load use their routes and each refusal is worded
`discoverTools(api, serverId, body, key, signal?)` SHALL post `body` to `/tool-servers/<id>/discover` with the header `Idempotency-Key` and resolve `parseDiscovery` of the answer, rejecting `RangeError` before a call for an id outside `^[a-z][a-z0-9_]{0,31}$`, a blank key or a body that is not `{ tools }` of an object, and `ApiRequestError` 200 `INVALID_RESPONSE` for an unreadable answer. `loadServerReview(api, serverId, signal?)` SHALL read `GET /tool-servers/<id>` once and resolve `{ server, approved, pending }`: `server` the `parseToolServer` view (`INVALID_RESPONSE` when `null`), the raw `approvedSurface` and `pendingSurface` each `null` when absent. `discoveryErrorText(error)` SHALL give the text of test-plan.md § Calls and errors for the `details.reason` of a 422 `OPERATION_REFUSED` (for `no_tools` with the tools left out, for `name_collision` with `details.names`, for `discovery_failed` with a status of `401` or `403` as a refused credential) and of a 503 `EGRESS_UNAVAILABLE`, else `toolsErrorMessage(error)`; `collidingNames(error)` SHALL give the names of a `name_collision` (two or more tool names of `^[A-Za-z0-9_.-]{1,128}$` joined by commas), else `[]`.

### Requirement: The server page shows discovery, settings, changes and calls
For an MCP server the page SHALL show a region named by `h2` "Discovery" with the button "Discover tools" (`aria-disabled` and inert while the detail loads, has failed or a discovery runs), which posts `discoverBody(initialDraft(tools))` with a fresh `Idempotency-Key`, `tools` being those of the approved surface (`[]` when it has none or is unreadable), so a rediscovery keeps the effects the admin set and `{ tools: {} }` is posted before any approval (D17a); with a readable pending surface, or after a `name_collision` refusal (the rows are then the colliding names), it SHALL show the table "Tool settings" with per row a textbox "Tool name of <server tool name>" (empty unless `initialDraft` gives a name) and a combobox "Effect of <server tool name>" (options "Proposed", "read", "write", "send", "pay", "Skip", starting at `initialDraft`), and the button "Discover again with these settings", which posts `discoverBody`; the draft is reset by each loaded detail. A success SHALL show `discoveryText` as a status and read the detail again; a refusal SHALL show `discoveryErrorText` as an alert and not read it. Every server SHALL show `h2` "Changes" with the list "Changes" (each item its text, then its lines) or the `changesView` text, and the table "Calls" of the pending surface, else the approved one, followed by the `readNote` sentence when it is not `null`. Steps: test-plan-browser.md.
