## Context

MCP is hand-rolled JSON-RPC over POST through the gateway, one request per policy decision (D11). U47b gives the seam (`CallAdapter`, `McpCallSpec`, store functions, invoke dispatch); this unit adds wire, adapter, discovery, registration and two routes. Taken shapes: `delivered-shapes.md`. `ServiceLookup` repeats `ServiceResolver`'s shape (`tools` may not import `credentials`); `main` passes `createServiceResolver(pool)`.

## Decisions

1. **Bytes and replies.** A request's id is its attempt number in a discovery and 1 in a call, so a call's digest depends on its arguments only; a `__proto__` member of `arguments` is defined, never assigned. `readMcpReply` splits SSE on a blank line, joins `data:` lines with `\n`, skips notifications and unparsable events. `answer`'s reasons are fixed words: no server text reaches `details`.
2. **Surface (R3, R4).** Schemas first, for `inputSchema` and `outputSchema`, found without recursion (a walk over schema positions: `properties`, `$defs`, `definitions`, `dependentSchemas`, `items`, `allOf`, `anyOf`, `oneOf`, `prefixItems`, `not`, `if`/`then`/`else`, `contains`, `additionalProperties`, `propertyNames`, `unevaluated*`; a property *named* `pattern` and the data of `enum`, `const`, `default` stay): a top-level `$schema` equal to the draft-07 or 2020-12 meta-schema URI (with or without `#`) is dropped (many servers declare draft-07, the MCP default is 2020-12, Ajv2020 refuses draft-07); `pattern` is dropped everywhere (a server regex such as `^(a+)+$` runs in the engine's Ajv: 30 characters of input take about 5 s) and `patternProperties` is `schema_invalid`, because dropping it would turn its members into `additionalProperties` failures; `$id` and `$anchor` are dropped (a second compile of a schema with the same `$id` fails every later call); a `$ref` that does not start with `#/` or does not name an existing member of the same schema, any `$dynamicRef` or `$recursiveRef`, tuple `items` arrays and an input property `url_host` (`toCedarArgs` refuses it, so every call would fail) are `schema_invalid`. Any other `$schema` stays and is `schema_invalid`. Then per tool, first match wins: `skipped` (overlay `skip: true`), `x_mcp_header`, `name_invalid`, `schema_invalid` (`inputSchema` not of `type` `object`, or `normalizeBlockImport` refuses it), `output_not_object`. `excluded[].name` replaces each character outside U+0020 to U+007E with `?` and is cut to 128 (a name with U+0000 or a lone surrogate would make the stored 200 body unstorable as `jsonb` and the web discovery a 500). A `description` over 2,000 characters or not well-formed is left out, the tool stays, and it is listed as `description`. Every lookup by a server tool name uses `Object.hasOwn` (`constructor`, `toString`, `__proto__` are valid names). More than 1,000 listed tools, or more than 100 not skipped, is `too_many_tools`. Defaults are `write`, `untrusted_result` true, `unsafe_to_retry` true; the overlay replaces each member alone (an overlay `read` does not clear `unsafe_to_retry`). An overlay entry for a tool the server no longer lists is skipped and reported as `not_listed` (D17b), so a rediscovery pre-filled from the approved surface still succeeds; its shape is checked first. The boolean annotation hints become `call.hints` (U47b's optional `McpCallSpec` member, checked and digested by U47b's code, so a changed hint is drift and this unit edits no seam file). A short `description` is carried: a changed description is drift (tool poisoning). U56b shows `call.hints` beside the effect. No server text, token, credential or session id reaches a `reason`, `details`, log or row.
3. **Registration and migration.** `registerMcpServerTx` parses the URL (WHATWG: dot segments are already removed), refuses a `?` (`query`: some servers put a key there, and no query credential exists), a `#`, a username or password and a path over 1,024 characters, takes `validateOrigin`'s reason, stores the origin with `registerAdapterServerTx` and the path in `mcp_server`, in one transaction. The CHECK is `char_length(endpoint) BETWEEN 1 AND 1024 AND endpoint ~ '^/[\x21-\x7e]*$' AND endpoint !~ '[?#]'`: Postgres refuses a repetition count over 255 (`{0,1023}` raises `2201B invalid repetition count(s)`); the `\x21-\x7e` escape works.
4. **Discovery (R2).** `server/discover` (modern): 2xx listing `2026-07-28` is modern, else `protocol_unsupported`; error `-32601` is modern and goes on; `-32020`, `-32021`, `-32022` are `protocol_unsupported`; 401 and 403 are `discovery_failed` (an auth failure is no era signal; the card says any 4xx is legacy); another 4xx is legacy; 5xx, a redirect or an unreadable 2xx is `discovery_failed`. Legacy: `initialize` `2025-11-25`, the answered version (in `MCP_LEGACY_VERSIONS`) is used from then on; an `mcp-session-id` header is `mcp_session_required` before anything more is sent; `notifications/initialized` must answer 2xx (card: 202; refusing 200 gains no safety); then `tools/list`, 10 pages at most. At most 13 round trips (card: 12). UNVERIFIED (M8): a stateless legacy server answers `tools/call` without `initialize`.
5. **Policy per request.** A rejected `policy.check` is `discovery_failed` `policy` (no decision exists); errors store a deny; an unrecorded decision is `decision`; a deny, an error or an allow without permit is `discovery_denied`; nothing is sent. A gateway rejection is `token` or `send`, except `GATEWAY_UNAVAILABLE`, which passes through. No credential is `credential_missing` before any decision.
6. **Routes.** The 503 for a null dependency comes first (the card puts it last). With an `Idempotency-Key` the discover route first calls `storedIdempotentReply` (a read-only lookup, added to `src/api/idempotency.ts`: it applies the same 24-hour window and digest rule as `withIdempotency`): a hit answers the stored body with `Idempotent-Replayed: true` and sends nothing, so the base rule "a write runs once per key" holds; another digest is 422 `IDEMPOTENCY_KEY_REUSED`. Otherwise `discoverMcp` runs with no transaction open (the e2e pools hold one connection), then `withIdempotency` wraps `submitAdapterSurfaceTx`; it settles two first requests that race (both discover, one submits, the other replays). The route recognises `GatewayError` by `name` and `code`, not by import: a second value import of the gateway would be a second egress site. A `TOOLS_REFUSED`'s `details` pass through as the strings they are (`reason`, `decisionId`, `stage`, `status`, `names`: one comma-joined string, as U56b's `collidingNames` reads it), except `excluded`, which the route answers as the array its JSON text holds (row T10).
