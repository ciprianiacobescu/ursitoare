## ADDED Requirements

### Requirement: A node id has at most 128 characters in the L1 schema
`src/authoring/validate/version.ts` SHALL export `VALIDATOR_VERSION` (2) and `MAX_NODE_ID_LENGTH` (128), and `$defs.nodeId` of the L1 schema SHALL be the pattern `^[a-z][a-z0-9_]{0,127}$`, built from `MAX_NODE_ID_LENGTH`, so every key of `nodes`, `start`, every `next`, `on_timeout`, `default` and every value of `cases` is bounded by it. A `nodes` key that matches the old pattern `^[a-z][a-z0-9_]*$` and is longer than 128 characters SHALL give an `L1_PATTERN` error at `/nodes/<id>` with the message `node id "<its first 32 characters>…" is too long: at most 128 characters`; every other pattern failure SHALL keep its message, and `FLOW_ERROR_CODES` SHALL stay at its 47 codes.

#### Scenario: 128 characters pass and 129 are refused with a fixed message
- **WHEN** `validateFlow` runs with `emptyCatalogue` on the rows N1 to N6 of `test-plan.md` § Node-id rows (a `go` wait node leading to an `end` node whose id is `id(n)`, that is `"x"` followed by `n - 1` times `"a"`), and `VALIDATOR_VERSION`, `MAX_NODE_ID_LENGTH` and `FLOW_ERROR_CODES.length` are read
- **THEN** the constants are 2 and 128 and `FLOW_ERROR_CODES` has 47 entries; lengths 1, 127 and 128 give `ok: true`, `errors: []`, `warnings: []` and `layers_run` `["L1", "L2", "L3"]`; lengths 129 and 200 give `ok: false`, `layers_run` `["L1"]` and exactly two `L1_PATTERN` errors, first at `/nodes/go/next` with the message `must match pattern "^[a-z][a-z0-9_]{0,127}$"`, then at `/nodes/<id>` with the "is too long" message; a 129-character `start` gives one `L1_PATTERN` at `/start`; a reference to a 129-character node gives one `L1_REF_SYNTAX` at `/nodes/done/output/v`; a 129-character key with an upper-case first letter keeps the old message `node id "<id>" is invalid: ids are snake_case and match [a-z][a-z0-9_]*`

### Requirement: A hook nodes selector can only name an existing node
The `nodes` members of a hook selector (`match`, and `when.from` and `when.next`) SHALL NOT be routed through `$defs.nodeId`: the L1 schema accepts `hooks` as an array of objects, and layer H accepts a `nodes` entry only when it is a string naming a key of the flow's `nodes` (`src/authoring/hooks/check.ts`). Because layer H runs only when L1 to L3 gave no error, and every `nodes` key has passed the 128-character bound, no selector entry can name a longer id; the selector gets no pattern of its own.

#### Scenario: A hook nodes selector is bounded by the nodes it names
- **WHEN** `validateFlow` runs with `emptyCatalogue` on the rows K1 to K4 of `test-plan.md` § Hook-selector rows (the `go` and `id(n)` flow with a `tag_end` rule whose `match` is `{ nodes: [<id>] }`)
- **THEN** K1 (a selector naming the existing 128-character node) is `ok: true` with `layers_run` `["L1", "L2", "L3", "H"]`; K2 (a 129-character node named by its rule) stops in L1 with the two `L1_PATTERN` errors of N2 and `layers_run` `["L1"]`, so layer H never saw it; K3 (a 129-character id that no node has) is `ok: false` with `layers_run` `["L1", "L2", "L3", "H"]` and one `H_SCHEMA` error at `/hooks/0/match/nodes/0` with the message `invalid entry in selector member nodes`; K4 (a selector naming the existing node `done`) is `ok: true`
