## MODIFIED Requirements

### Requirement: Node runtimes are registered once per kind
`registerNodeRuntime` SHALL register one runtime per `NodeKind` and refuse a second one or one without `execute`; `block`, `code`, `end`, `switch` and `wait` SHALL be built in.

#### Scenario: Built-in kinds and registration rules
- **WHEN** `nodeRuntimeFor` gets each of the 14 `NODE_KINDS` and `"constructor"`; then, with `RT = { execute: async () => OUTCOME }` (any outcome), `registerNodeRuntime` gets `("block", RT)`, `("human.form", {})`, `("nope", RT)`, `("human.form", RT)` and `("human.form", RT)` again
- **THEN** `SUPPORTED_KINDS` deep-equals `["block", "code", "end", "switch", "wait"]`; the lookups return a runtime with a function `execute` for exactly those five kinds, `undefined` otherwise, and the runtime for `code` is `codeRuntime`; the calls throw `InterpreterError` with `code` and `details.kind`: `NODE_RUNTIME_DUPLICATE` `block`, `NODE_RUNTIME_INVALID` `human.form` and `nope`; the fourth returns, then `nodeRuntimeFor("human.form") === RT`; the fifth throws `NODE_RUNTIME_DUPLICATE`

### Requirement: A run starts only by registry id and hash
`startRun` SHALL load the version through `loadVersion`, refuse a missing, `draft`, unsupported-kind, unknown-block or ill-typed-input start, or a load rejection, without storing a run, store a `queued` run owned by the version's team, enqueue `ursitoare.run` under `workflowIdOf(tenantId, runId)` (`tenantId:runId`), and answer the stored run for a known id.

#### Scenario: Refusals, enqueue and idempotence
- **WHEN** `startRun` gets, each alone with a recording `enqueue`: an unknown flow id; `pay-draft`; `rf-1-core`; `pay-missing`; `pay-once` with input `{ vendor: "Acme" }`; `pay-once` with `runId` `bad id`; then `pay-once` with `runId` `r_7` and `mocks: { lookup: {} }` as `T_A`, twice (the second with another valid input), once as `T_B`, once as `T_U`, once with no `runId` under `sequentialIds(0)`, once with `durable: null`, and once with `enqueue` rejecting `new Error("down")`, and with `loadVersion` and `catalogueFor` each rejecting
- **THEN** the refusals throw `InterpreterError` `INTERPRETER_VERSION_NOT_FOUND`; `INTERPRETER_VERSION_NOT_RUNNABLE` with `details.reason` `draft`; `INTERPRETER_KIND_UNSUPPORTED` with `details.kinds` `["llm.decide", "llm.extract"]`; `INTERPRETER_VERSION_NOT_RUNNABLE` with `details.reason` `block_missing`, `details.blocks` `["erp.unknown@1"]`; `INTERPRETER_INPUT_INVALID` with `details.path` `/`; `INTERPRETER_INPUT_INVALID` with `details.field` `runId`; none stores a run or calls `enqueue`, and the two rejections reject with the same error object; the `r_7` call returns the run `queued` with `lineageId` `r_7`, `ownerTeam` `finance`, `trigger` `test`, `inputRef` and `mocksRef` the digests of input and mocks, and `enqueue` got `("ursitoare.run", "tenant_a:r_7", ENQ("tenant_a", "r_7"))`; the second returns an equal record and `enqueue` got the same arguments again; the `T_B` call stores a second `r_7` (each reads only its own) and `enqueue` got `("ursitoare.run", "tenant_b:r_7", ENQ("tenant_b", "r_7"))`; `workflowIdOf("tenant_a", "r_7")` is `tenant_a:r_7` and `workflowIdOf("_t", "r_7")` is `_t:r_7`, which the `T_U` call enqueued under; no-id returns `runId` `run_00000000-0000-7000-8000-000000000000`; `durable: null` enqueues nothing; the rejecting enqueue makes `startRun` throw `INTERPRETER_UNBOUND`, leaving the run `failed` with that code and a message without `down`
