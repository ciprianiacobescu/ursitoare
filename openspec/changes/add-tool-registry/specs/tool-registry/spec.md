## Purpose

Tool servers a tenant admin registers, their surfaces, approval by a second admin (an audited self-approval when solo), the immutable bound block versions approval writes, the directory that resolves a block ref, and the drift rule.

## ADDED Requirements

### Requirement: Tool servers and their surfaces are stored per tenant and only approvals update them
Migration `0470_tool_registry.sql` SHALL create `tool_server (tenant_id, tool_server_id, adapter, origin, local, state, registered_by, registered_at, approved_digest)` with primary key `(tenant_id, tool_server_id)` and `tool_surface (tenant_id, tool_server_id, surface_digest, surface, submitted_by, submitted_at, approved_by, approved_at, self_approved)` with primary key `(tenant_id, tool_server_id, surface_digest)` and a foreign key to `tool_server`, both with forced row level security on `app.tenant_id`; the app role SHALL hold SELECT and INSERT on both, UPDATE only on `tool_server (state, approved_digest)` and `tool_surface (approved_by, approved_at, self_approved)`, and no DELETE. A server SHALL be `pending` exactly when its `approved_digest` is null, and the three approval columns of a surface SHALL be all set or all null.

### Requirement: validateOrigin accepts public https origins and refuses unsafe ones
`validateOrigin(url, { local })` SHALL return `{ ok: true, origin }` (`scheme://host[:port]`, lower case, no trailing dot, default port or slash) or `{ ok: false, reason }` by the order and classes of design.md § validateOrigin, with no DNS lookup; an IPv6 literal host that no class refuses SHALL be `ipv6`, because the PDP's permit host pattern admits no bracketed host. Names under `fake.test` SHALL be ordinary public names.

### Requirement: The surface digest is canonical, fixtureSurface builds fixture surfaces, and block refs are chosen by content
`surfaceDigest(surface)` SHALL ignore the order of tools and of `untrusted_fields`, treat absent optional members as their defaults and change when any field of any tool changes (design.md § The digest and fixtureSurface). `fixtureSurface(refs, opts)` SHALL return one tool per test-catalogue ref and throw for an unknown ref or two refs of one tool name. `surfaceRefs(serverId, surface, taken)` SHALL give each tool `${serverId}.${name}@${major}` for the lowest major from 1 whose ref is absent from `taken` or held there with the tool's block content hash, and SHALL read no database.

### Requirement: Registering a server stores it pending with its first surface
`registerToolServer` and `registerToolServerTx` (the same in the caller's transaction) SHALL check the id, the adapter (an unknown value is `TOOLS_INVALID`, any but `fixture` `TOOLS_REFUSED` `adapter_unavailable`), the origin and the surface (design.md § The surface check) in that order, then store the server `pending`, its surface and the event `tools.server_registered`. An existing id SHALL be `TOOLS_EXISTS`; a transaction of another tenant than `ctx` SHALL be `TOOLS_TENANT_MISMATCH` before any write. A record's `pendingDigest` SHALL be that of the newest submitted surface while it is unapproved, else null, and its `pendingSubmittedBy` that surface's `submitted_by`, else null; its `tools` those of the approved surface with refs, or of the pending one with null refs.

### Requirement: Approval needs another admin in a team and an explicit, audited self-approval when solo
`approveSurface` SHALL refuse, in order, an unknown server (`TOOLS_NOT_FOUND`), then with `TOOLS_REFUSED` and `details.reason`: `nothing_pending`, `digest_mismatch`, `approver_is_submitter` (team, the approver submitted the pending surface) and `self_approval_required` (solo, the approver submitted it, `selfApproval` not `true`); a refusal SHALL write nothing. The submitter's flagged solo approval SHALL set `self_approved` true and append `tools.surface_self_approved`; any other approval sets it false and appends `tools.surface_approved`; both payloads are `{ digest, refs }`.

### Requirement: Approval writes immutable bound block versions and a failure between its two steps leaves them inert
Approval SHALL call `importCatalogue` with the refs of `surfaceRefs` and, per tool, its block with `binding` `{ server, tool }` (design.md § The block of a tool), then in one transaction set the approval columns, the server's `state` `approved` and `approved_digest`, and append the audit event. A `REGISTRY_CONFLICT` SHALL be `TOOLS_REFUSED` `ref_conflict`. Blocks stay inert until the server is `approved`, so a repeat after a failure finds them `unchanged` and completes.

### Requirement: A changed surface disables the server until its new digest is approved
`submitSurface` SHALL throw `TOOLS_NOT_FOUND` for an unknown server and check the surface as at registration; the approved digest or the newest unapproved digest SHALL change nothing; any other stored digest SHALL be `TOOLS_REFUSED` `surface_known`; a new digest SHALL be stored as the newest surface, set an `approved` server to `drifted` (approved digest and tools unchanged) and append `tools.surface_submitted` `{ digest, drift }` (`drift` true when the server has an approved digest). Only approval of the pending digest SHALL return it to `approved`.

#### Scenario: A submitted surface drifts an approved server and re-approval restores it
- **WHEN** `acme` is approved on `SURF_A` and `beta` on `SURF_ONE` (ALICE, solo, flagged), `gamma` is registered; DAVE submits, advancing `CLOCK` by 1000 ms before each, the six surfaces of test-plan.md § Submit calls for `acme`, then `SURF_ONE_T` for `beta` and for `gamma`; CAROL approves `D_B` in a team; `SURF_A` is submitted again
- **THEN** the six calls return `REC_APPROVED_A`, `REC_DRIFTED` three times (resubmitting the approved digest does not restore `approved`), then throw `TOOLS_INVALID` `{ field: "tools/0/http/method", reason: "method_without_body" }` and `TOOLS_NOT_FOUND` `{ id: "nope" }`; `beta` is `drifted` with `pendingDigest` `D_ONE_T`, `gamma` `pending` with `pendingDigest` `D_ONE_T` and `approvedDigest` null; the `tools.surface_submitted` payloads are `{ digest: D_B, drift: true }`, `{ digest: D_ONE_T, drift: true }`, `{ digest: D_ONE_T, drift: false }`; CAROL's approval returns `REC_APPROVED_B` with blocks `["acme.create_payment@1", "acme.lookup_vendor@2"]`; the last call throws `TOOLS_REFUSED` `{ reason: "surface_known" }`

### Requirement: The directory resolves a ref only to the approved definition of a bound tool
`createToolDirectory(pool).resolve(ctx, ref)` SHALL return `null` unless the block version has a binding of exactly `{ server, tool }` (two strings), `ref` starts with `${server}.${tool}@`, the server has an approved digest, the approved surface holds the tool, and the block that tool yields has the version's content hash; otherwise a `ToolBinding` with the server's `state` (`drifted` included). A database failure SHALL reject, never answer `null`.

- **THEN** each result deep-equals its row, among them `acme.lookup_vendor@1` is `BIND_LV_1` while approved, the same with `state` `drifted` once `SURF_B` is submitted, `null` once `D_B` is approved; `acme.lookup_vendor@2` is `BIND_LV_2`; `acme.create_payment@1` is `null` once `SURF_E` is approved; unbound, unknown, foreign-prefix and malformed-binding refs and the ref for `T_B` are `null`; the failing pool rejects with message `db down`
