## ADDED Requirements

### Requirement: The audit sink is enabled by one variable and the engine holds no token
`loadAuditSinkConfig(env, base)` SHALL return `undefined` when `URSITOARE_AUDIT_SINK` is unset or empty, `{ enabled: true }` when it is exactly `enabled` and `base.database.app` is not `null`, and otherwise throw `ConfigError` `CONFIG_INVALID` naming `URSITOARE_AUDIT_SINK`: `must be enabled or unset` for any other value (a bad value wins over a missing database), `requires URSITOARE_DATABASE_URL` for `enabled` without an app database. `loadConfig` SHALL add `auditSink` to the `AppConfig` only when `loadAuditSinkConfig` returned a value. The engine SHALL read no sink token: no `AuditSinkConfig` member, no variable and no secret read holds one, and `URSITOARE_AUDIT_SINK_BROKER_TOKEN_FILE` and `URSITOARE_AUDIT_SINK_PROXY_TOKEN_FILE` stay variables of the owner command `tenant-sink`, never of `loadConfig`.

#### Scenario: Enabled, unset and refused values
- **WHEN** `loadConfig` runs on rows A1 to A5 of test-plan.md § Config with a recording `SecretReader` that throws, and `loadAuditSinkConfig` runs on `({ URSITOARE_AUDIT_SINK: "enabled" }, { database: { app: {} } })` and on `({}, { database: { app: null } })`
- **THEN** A1 and A2 give a config whose own keys are exactly `database`, `engineKey`, `host`, `internalPort`, `logLevel`, `port`, `publicBaseUrl`, `role`, `shutdownDrainMs`, `webDist` (no `auditSink`); A3 adds `auditSink` equal to `{ enabled: true }` and nothing else; A4 (`Enabled`, `true`, `1`, `disabled`, ` enabled`) and A5b throw `CONFIG_INVALID` with `variable` `URSITOARE_AUDIT_SINK` and message `URSITOARE_AUDIT_SINK: must be enabled or unset`; A5 throws with message `URSITOARE_AUDIT_SINK: requires URSITOARE_DATABASE_URL`; the direct calls return `{ enabled: true }` and `undefined`; the reader is never called

#### Scenario: The engine reads no token file
- **WHEN** `loadConfig` runs on row A6 (the sink enabled, an app database, both `URSITOARE_AUDIT_SINK_*_TOKEN_FILE` variables set to `/nonexistent/broker` and `/nonexistent/proxy`) and on row A7 (`URSITOARE_AUDIT_SINK_BROKER_TOKEN` set to `abc123`)
- **THEN** A6 resolves with `auditSink` equal to `{ enabled: true }`, the reader's recorded calls are `[]`, and `JSON.stringify` of the whole config holds neither `/nonexistent` nor `TOKEN`; A7 throws `CONFIG_INVALID` with `variable` `URSITOARE_AUDIT_SINK_BROKER_TOKEN` and message `URSITOARE_AUDIT_SINK_BROKER_TOKEN: secrets are read only from files; set URSITOARE_AUDIT_SINK_BROKER_TOKEN_FILE` (the existing rule), with no `abc123` in it
