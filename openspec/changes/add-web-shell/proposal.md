## Why

The roadmap's first milestone ends with a person opening the engine's address in a browser and seeing the product. Today the engine answers only `GET /health` and `web/src/main.tsx` is a one-heading placeholder. Every later UI unit needs the same four things and would otherwise invent them: a page shell with landmarks and a skip link, one place to add a route and a nav entry, one client for the `/api/v1` error envelope, and a static host that is safe by default (exact security headers, no path traversal, no HTML pretending to be an API answer).

Observable result: with `web/dist` built (`pnpm run build`, which every gate run executes before the test and e2e gates), `GET /` on the engine returns the app. The page has a banner with the product name, a main navigation, a main area and a footer, a "Skip to content" link, and the heading "Ursitoare" with the text "Engine healthy" (or "Engine unavailable" with a "Check again" button, after a "Checking engine health" loading state) taken from `GET /health`. A deep link such as `/flows` returns the same app, which shows "Page not found" under the title `Page not found · Ursitoare`. Every response of the engine that `main` starts (not `startServer`'s) carries the exact Content-Security-Policy (no `unsafe-inline`, no `unsafe-eval`), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` and `X-Frame-Options: DENY`. `GET /api/v1/does-not-exist` answers 404 `{ "error": { "code": "NOT_FOUND", ... } }`, never HTML; `/../../etc/passwd` and its encoded variants answer 404 and read no file outside `web/dist`. Without a build, the engine still starts, logs one warning, and `GET /` answers 503 `WEB_NOT_BUILT` with a hint; a `distDir` that is not a web build serves no file. The browser journey `e2e/test_m0_skeleton.py` proves all of it through the offline e2e stack.

## What Changes

- `src/api`: `registerWebApp(server, { distDir })` (static files, SPA fallback, cache headers, 404 and 503 envelopes), `isWebBuilt`, `registerSecurityHeaders(server)`, `classifyWebPath`, `DEFAULT_WEB_DIST`, `WebAppError`.
- `src/main.ts`: `main` calls `registerWebApp` with `config.webDist` (`URSITOARE_WEB_DIST`; unset means `DEFAULT_WEB_DIST`, applied in `main`, while `AppConfig.webDist` stays `null`) logs one warning when the build is missing, and on a `WebAppError` closes the database and writes the single fatal line.
- `test/support/e2e-stack/web-part.ts` and `parts/20-web.ts`: the stack hands the engine the absolute `web/dist` path; the part is discovered, no shared file changes.
- `web/src`: `api/client.ts` (`createApiClient`, `ApiRequestError`), `app/features.ts` (`registerFeature`, the nav and its capability filter), `app/routes.ts`, `app/health.ts` (engine health state and the view rule), the shell, landing page and unknown-route page, `features/10-home.tsx` and a `features/index.ts` that collects `NN-<name>.tsx` files, and the new `main.tsx`.
- `react-router` 7.18.4 is already installed, exact-pinned in `web/package.json` and `pnpm-lock.yaml` by the owner on 2026-10-25, before the plan runs; no task adds it.
- `e2e/test_m0_skeleton.py`: the M0 journey.
