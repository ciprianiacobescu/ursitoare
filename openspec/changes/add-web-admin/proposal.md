## Why

M2 gives the engine roles, teams, group mappings, an admin API and an audit API, but an administrator can reach them only with raw HTTP or the command line. This change adds the screens, and it closes milestone M2 with the browser journey that shows the whole milestone working: an administrator maps a group and reads a verified audit log, and a person without the right is refused with a decision id.

Observable result: carol (group `ursitoare-admins`, role `tenant_admin`) sees "Users", "Roles and teams", "Group mappings" and "Audit log" in the main navigation, alice (role `author`) sees none of them. Carol lists the tenant's people and disables or enables one after a confirmation that names them (the person's open sessions end at once), creates and deletes teams, lists roles, maps an identity provider group to one role or team and removes a mapping after a confirmation that states what its members lose, and reads the audit log newest first, filtered by event type, under a status that says "Audit chain verified" or "Audit chain broken" at an event number. Alice, opening `/admin/users` by address, gets the API's refusal as a "Not allowed" panel with the decision id and a "Copy decision id" button, and carol finds the same id in her audit log. Every control has a name, every table has a caption, loading, empty and error states are shown, and `assert_accessible(page)` passes on each page.

## What Changes

- `web/src/admin/`: the logic (`shared.ts`, `pages.ts`, `messages.ts`, `users.ts`, `teams.ts`, `mappings.ts`, `audit.ts`) with Node tests, the thin components `UsersPage.tsx`, `TeamsPage.tsx`, `MappingsPage.tsx`, `AuditPage.tsx` and `admin.css`.
- Four feature files `web/src/features/60-admin-users.tsx` to `63-admin-audit.tsx`, collected by the existing glob.
- `test/journeys/session.ts` and `m2-admin.test.ts`: the logic run against the real engine of the e2e stack. `e2e/test_m2_admin.py`: the browser journey.
