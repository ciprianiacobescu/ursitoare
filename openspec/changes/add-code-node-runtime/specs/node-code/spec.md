## Purpose

The `node-code` capability runs a flow's pure `code` nodes: the source runs on the injected sandbox pool inside the node's durable step, its object is checked against `output_schema`, every sandbox fault is a terminal typed run failure, and the engine owns the pool.

## ADDED Requirements

### Requirement: A code node returns the sandbox object after its schema check
`codeRuntime` SHALL, in one step named by the node id, check that `services.sandbox` exists, resolve `node.input`, call `services.sandbox.run(node.source, <the resolved input>, CODE_LIMITS, { seed: codeSeed(ctx), nowIso: ctx.now.toISOString(), binding: "input", result: "object" })`, check the object against `node.output_schema`, and return `{ output, outcome: null, next: node.next ?? null, end: null }`.

#### Scenario: The call, the outcome and the schema checks
- **WHEN** `codeRuntime.execute(NORM_NODE(NORM_SRC), CTX("normalize"), services)` runs over `memoryWorkflowOps("r_1")` and `SCOPE` with `REC` answering `ok` with `NORMALIZED`; then with `REC` answering `{ amount: 1, currency: "EUR", is_large: "yes" }`, `{ amount: 1, currency: "EUR" }` and `{ amount: "x", currency: "EUR", is_large: true }`; then with `input` `{ amount: "${{ inputs.missing }}" }` and with a node that has no `next`
- **THEN** the first call resolves `{ output: NORMALIZED, outcome: null, next: "pay", end: null }`; its `REC` holds exactly one call, deep-equal `{ code: NORM_SRC, input: { amount: 1234.567, currency: "eur" }, limits: CODE_LIMITS, options: { seed: "r_1:normalize:1", nowIso: "2026-11-02T10:00:00.000Z", binding: "input", result: "object" } }`, and the ops `executed` is `["normalize"]`; the three bad answers reject `InterpreterError` `INTERPRETER_OUTPUT_INVALID` with `node` `normalize`, message `output of "normalize" does not match its output_schema` and `details` `{ path: "/is_large", keyword: "type" }`, `{ path: "/", keyword: "required" }`, `{ path: "/amount", keyword: "type" }`; the unresolved input rejects `INTERPRETER_REF_UNRESOLVED` with `node` `normalize` and `details.ref` `inputs.missing`, and its `REC` holds no call; the node without `next` resolves with `next` null

### Requirement: The seed and the limits of a code node are fixed
`codeSeed(ctx)` SHALL return `${ctx.runId}:${ctx.nodeId}:${ctx.attempt}`, and `CODE_LIMITS` SHALL be frozen and equal `DEFAULT_SANDBOX_LIMITS`, so the same run, node, attempt and `ctx.now` always give the same output.

#### Scenario: Seed strings, limits and repeatable output
- **WHEN** `codeSeed` gets `CTX("normalize")`, the same with `attempt` 2, and a context with `runId` `run_00000000-0000-7000-8000-000000000000`, `nodeId` `n`, `attempt` 12; `CODE_LIMITS` is read; and on `POOL()` `codeRuntime.execute` runs the node `RAND` (`RAND_SRC`, schema `ANY`) with `CTX("rand")` three times, with `CTX("rand", 2)`, and with `CTX("rand", 1, new Date("2026-11-03T10:00:00Z"))`
- **THEN** the seeds are `r_1:normalize:1`, `r_1:normalize:2` and `run_00000000-0000-7000-8000-000000000000:n:12`; `CODE_LIMITS` is frozen and deep-equals `DEFAULT_SANDBOX_LIMITS` and `{ timeoutMs: 1000, memoryBytes: 33554432, maxStackBytes: 262144, maxOutputBytes: 1048576 }`; the three first outputs are deep-equal, with `t` 1793613600000, `iso` `2026-11-02T10:00:00.000Z` and `r` a number in `[0, 1)`; attempt 2 gives the same `t` and `iso` and a different `r`; the later `now` gives the `r` of attempt 1, `t` 1793700000000 and `iso` `2026-11-03T10:00:00.000Z`

### Requirement: A code node fault is terminal and typed
`codeRuntime` SHALL call `sandbox.run` at most once per visit and throw `InterpreterError` `INTERPRETER_CODE_FAILED` (message `code node "<id>" failed (<fault>)`, `node` the id, `details` `{ fault }`) for a sandbox fault, with `fault` `sandbox_unavailable` when `run` rejects; `INTERPRETER_NO_SANDBOX` (message `no sandbox is available for code node "<id>"`) when `services.sandbox` is absent; and `INTERPRETER_OUTPUT_INVALID` (message `output of "<id>" cannot be stored`, `details` `{ path: "/", keyword: "payload" }`) when the object fits `output_schema` but `payloadDigest` refuses it (U+0000, an ill-formed string, more than 64 nested containers); the guest's message SHALL NOT enter an error, and an `output_schema` miss whose path is ill formed, holds U+0000 or is longer than 256 characters SHALL report `details.path` `/`, so the run error stays storable (`jsonb`). Both new codes SHALL be in the `InterpreterErrorCode` union and in `INTERPRETER_ERROR_CODES`.

#### Scenario: Faults, a missing sandbox, unstorable output and no leak
- **WHEN** on `POOL()` `runConformance("code", codeRuntime, CASES)` runs the 14 cases of `test-plan.md` (`loop` timed alone, `rss` read around `bomb`); each error case also runs through `codeRuntime.execute` over `memoryWorkflowOps("r_1")` with `CTX("node_under_test")`; for each of the ten `SandboxFaultCode` values `execute` runs with a `REC` answering that fault with the message `secret-token-123`, with a sandbox whose `run` rejects `new SandboxError("SANDBOX_CLOSED", "closed")`, and with one rejecting `new Error("pool secret-token-123")`; and `toInterpreterError` gets a plain `Error` copy of each new code (own `code`, `node`, `details`)
- **THEN** all 14 verdicts are `{ ok: true, detail: "" }`; `loop` takes 1000 to 3250 ms and `process.memoryUsage().rss` grows by at most 268435456 bytes over `bomb`; each error case rejects with its row's `code` and `details`, the message this requirement and requirement 1 give, and `node` `node_under_test`, and `JSON.stringify` of its message and details lacks `secret-token-123`; each of the ten fakes rejects `INTERPRETER_CODE_FAILED` with `details.fault` equal to its code, the message `code node "node_under_test" failed (<code>)` and exactly one recorded call; the two rejecting sandboxes reject `INTERPRETER_CODE_FAILED` with `details.fault` `sandbox_unavailable` and a message lacking `secret-token-123`; `toInterpreterError` returns an `InterpreterError` with the copy's `code`, `node` and `details`

### Requirement: A run walks code nodes as numbered steps
`startRun` SHALL admit a flow with `code` nodes; `executeRun` SHALL write for a `code` node a row of kind `code` with the resolved input and the object as payloads, reuse the recorded step value on a replay without calling the sandbox, and fail the run `INTERPRETER_NO_SANDBOX` at the node when `InterpreterDeps.sandbox` is absent.

#### Scenario: code-pay, its replay and a run with no sandbox
- **WHEN** `validateFlowText(CODE_PAY_TEXT, "yaml", loadTestCatalogue())` runs; then on a memory store with `codePayVersion()`, an `invokerFor` resolving a recording invoker that answers `LOOKUP_OK` and `PAID`, `NO_EFFECT_GATE`, `CLOCK` and `sandbox` a `COUNT(POOL())`, `startRun` (mode `mock`, `PAY_INPUT`, `runId` `r_cp`) and `executeRun` over a recording wrapper of `memoryWorkflowOps("r_cp")` run; `executeRun` runs again over `memoryWorkflowOps("r_cp", <the values the wrapper recorded>)`; and `r_cp2` runs the same way on deps without `sandbox`
- **THEN** validation gives `{ ok: true, errors: [], warnings: [], layers_run: ["L1", "L2", "L3"] }`; `r_cp` is `completed`, `terminalNode` `done`, output payload `{ payment_id: "pay-1" }`; the wrapper's steps are `["run:load", "run:start", "lookup", "normalize", "pay", "pay#done", "done", "run:finish"]`; `listSteps` gives `seq` 0 to 3 for `lookup`, `normalize`, `pay`, `done` with kinds `block`, `code`, `block`, `end`, and the `normalize` row is `completed` with `inputRef` `payloadDigest({ amount: 1234.567, currency: "eur" })`, `outputRef` `payloadDigest(NORMALIZED)`, `outcome` null, `taint` `[]`, `attempt` 1, `generation` 0, `idemKey` null; the invoker saw `lookup` with `{ vendor_name: "Acme" }` and `pay` with `PAY_ARGS`; the counter reads 1; the replay returns a run deep-equal to the first and leaves `listSteps` and the counter unchanged; `r_cp2` is `failed` with `error` `{ code: "INTERPRETER_NO_SANDBOX", message: "no sandbox is available for code node \"normalize\"", node: "normalize" }`, `terminalNode` `normalize`, two rows (`lookup` completed, `normalize` failed with that error) and no `pay` call

### Requirement: A sandbox fault fails its run once and the pool survives
On DBOS, `executeRun` SHALL end a run whose code node exhausts the sandbox memory or recurses without end `failed` with `INTERPRETER_CODE_FAILED`, call the sandbox once for it, and leave the pool able to run the next flow (exit test 15). No scenario replays a failed step.

#### Scenario: A memory bomb and a deep recursion on DBOS
- **WHEN** with `DBOS_SETUP` the runs `r_ok1` (`solo-ok`, `{ n: 1 }`), `r_bomb` (`solo-bomb`), `r_deep` (`solo-deep`) and `r_ok2` (`solo-ok`, `{ n: 41 }`) start in turn, each awaited with `waitForRun` for `completed` or `failed`; `process.memoryUsage().rss` is read after `r_ok1` and after `r_ok2`
- **THEN** `r_ok1` and `r_ok2` are `completed` with output payloads `{ n: 2 }` and `{ n: 42 }`; `r_bomb` and `r_deep` are `failed` with `terminalNode` `work` and `error` deep-equal `{ code: "INTERPRETER_CODE_FAILED", message: "code node \"work\" failed (memory_limit)", node: "work", details: { fault: "memory_limit" } }` and the same with `stack_overflow`; each has one row, `work`, kind `code`, `failed`, with that error; the recorded `options.seed` values are exactly `["r_ok1:work:1", "r_bomb:work:1", "r_deep:work:1", "r_ok2:work:1"]`, every `limits` deep-equals `CODE_LIMITS` and every `options` is `OPT(seed)`; the pool's `respawns` is 0; the observer's `before` steps of `tenant_a:r_bomb` are `["run:load", "run:start", "work", "run:finish"]`; `rss` grew by at most 268435456 bytes

### Requirement: The engine owns one sandbox pool
`main` SHALL, with an app endpoint and the role `all` or `worker`, create one pool with `(deps.createSandbox ?? createWorkerSandbox)({ size: poolSize(availableParallelism()) })` before it binds the interpreter, put it in `InterpreterDeps.sandbox`, and close it after the durable runtime and before the database (a failed start included); nothing else creates a pool, and `/health` `checks` stay `{ db: "ok" }`.

#### Scenario: Roles, closing order and failed starts
- **WHEN** `main` runs through a `const` deps object with `openDatabase` recording `database.close`, `launchDurable` returning a runtime that records `durable.shutdown`, `bindInterpreter` capturing its argument and `createSandbox` recording its arguments and returning a fake that records `sandbox.close`, for the roles `all` and `worker` with an app endpoint (stopped by SIGTERM), `api` and `sandbox` with one, and `all` with none; then for `all` with `launchDurable` rejecting `new Error("boom")`; then for `all` with `createSandbox` throwing `new SandboxError("SANDBOX_INVALID", "bad size", { option: "size" })`
- **THEN** for `all` and `worker` `createSandbox` got exactly `[{ size: poolSize(availableParallelism()) }]` (computed in the test), the captured deps' `sandbox` is the fake, the records are `["durable.shutdown", "sandbox.close", "database.close"]` and the exit codes `[0]`; for the other three `createSandbox` has no call and the records are `["database.close"]`; the `boom` start exits `[1]` with one fatal line whose `code` is `STARTUP_FAILED` and the records `["sandbox.close", "database.close"]`; the `SandboxError` start exits `[1]` with one fatal line whose `code` is `SANDBOX_INVALID`, no `launchDurable` call and the records `["database.close"]`; in `readSnapshot()` no non-test file under `src/` other than `src/main.ts` and those in `src/sandbox/` contains `createWorkerSandbox(`

### Requirement: A mock test run executes code nodes for real
The test endpoint SHALL start a mock run of a flow with `code` nodes, run each code node on the engine's pool and never answer it from a mock, so that F3 exercises the code before review.

#### Scenario: code-pay through main, a mock for a code node and shutdown
- **WHEN** on `withTestDatabase()` after `seedFlowActors` (alice, author of `finance`), `seedMockRunFlows` and `seedCodePay(db, a, CLOCK)`, `main` (role `all`, app and owner endpoints, `createSandbox` calling `createWorkerSandbox` and wrapping it with `COUNT`) serves; alice posts to the validated `code-pay` version `{ input: PAY_INPUT, mocks: { lookup: [{ output: LOOKUP_OK }], pay: [{ output: PAID }] } }`, then the same body plus `normalize: [{ output: NORMALIZED }]`; `GET /health` is read; `running.close()` runs, then a `run` on the wrapped pool
- **THEN** the first answer is 202 and `waitForRun` reaches `completed` with `terminalNode` `done` and output payload `{ payment_id: "pay-1" }`; the `normalize` row has kind `code` and an `outputRef` whose payload deep-equals `NORMALIZED`; the counter holds one call, with `code` equal to the `source` of `codePayVersion().flow.nodes.normalize` and `options.seed` `<runId>:normalize:1`; the second answer is 422 `TEST_MOCK_INVALID` with `details.problems` `[{ nodeId: "normalize", index: null, reason: "not_a_block", detail: "node is not a block" }]`; `/health` answers 200 with `checks` `{ db: "ok" }`; the late `run` rejects with a `SandboxError` of `code` `SANDBOX_CLOSED`
