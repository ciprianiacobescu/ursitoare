## What the fingerprint takes from add-hook-checker (U41, M5), restated

From the M5 folder `openspec/changes/add-hook-checker/` (design 1 and 2, specs/hooks-static, its Interfaces block). The fingerprint depends on exactly the rules below and on nothing else of that unit. `effectClass` is on main (`src/authoring/taint/hooks.ts:40`), `successorFields` and `hookValueFields` at `src/authoring/format/nodes.ts:80,67`.

- **Meta and selector.** `nodeMeta(flow, id, catalogue)` is `null` unless `id` is an own key of `flow.nodes` with an object value, else `{ id, kind: String(node.kind), effect: effectClass(node, catalogue) ?? null, tags }` (`tags` the node's `tags` when a string list, else `[]`). `selectorMatches(sel, meta)` is `false` for a `null` meta, `true` for an `undefined` selector, `false` for a non-object one; a field (`kind`, `effect`, `nodes`, `tags`) that is present and not a list makes it `false`; otherwise the present fields are AND-ed: `kind` holds `meta.kind`, `effect` holds `meta.effect` (never when `null`), `nodes` holds `meta.id`, `tags` shares one entry with `meta.tags`; an empty list matches nothing.
- **Placements.** `hookPlacements(flow, id, catalogue)` is `{ pre: [], post: [] }` for a `null` meta and for the kinds `agent`, `foreach`, `human.form`, `subflow`; an `end` node has no `post`. A rule of `flow.hooks` counts when it is an object with a string `id` and its `match` is absent (every node) or matches the meta; other entries are skipped. `pre` is the `pre` hook of each counting rule that has one, in declaration order, then the node's own `pre` entries (objects only) in order. `post` is the node's own `post` entries in order, then the `post` hook of each counting rule that has one, in reverse declaration order.
- **Members of a placement.** `phase`; `hook`, the same object as in the flow with every member as written; `ruleId`, the rule's `id` or `null`; `label`, the node hook's string `id` (else `""`) or `rule.<ruleId>`. The fingerprint hashes `phase`, `label`, `hook.kind`, `uses` or the sha256 of `source`, the `hookValueFields` (`input`, and `with` for a block hook) and `when`, `routes`, `max_retries`, `allow_effect_retry`, `on_error` when present; `ruleId` is not hashed.
- **`when`.** Placement never evaluates or filters on a hook's `when`: a hook whose `when` can never hold is placed all the same. The fingerprint hashes the `when` object as written in the flow document, never evaluated. Layer `H` (`checkHooks`) is not called; a flow that `checkHooks` would refuse (for example `H_ROUTE_EFFECT`) still has a fingerprint under these rules.
- **Routes.** `hookRoutes` is the string entries of `routes` of the `post` placements, first-seen, whatever their `when`. `augmentedSuccessors(flow, catalogue)` has one key per own node, its value the ids from `successorFields(node)` that name an own node, then the `hookRoutes` that name an own node, without repeats (a route to no node, such as `nowhere`, is dropped). `predecessors` and the dominating approvals use only which ids the lists hold.
