## Purpose

Effect intents and idempotency keys: a tenant-isolated journal that records an intent before every consequential tool call, a lineage-derived key that survives recovery and forks, and an effect gate that makes a kill between the intent and the done produce one effect.

## ADDED Requirements

### Requirement: The idempotency key follows ADR-08
`idemKey(tenantId, lineageId, nodeId, effectSeq, generation = 0)` SHALL return `"ik1_"` followed by the lowercase hex SHA-256 of the UTF-8 text `JSON.stringify([tenantId, lineageId, nodeId, effectSeq, generation])`, `lineageOf(run)` SHALL return `run.lineageId`, and a part outside its pattern SHALL be refused with `IntentError` `INTENT_INVALID`.

#### Scenario: Key vectors and refusals
- **WHEN** `idemKey("tenant_a", "r_1", "pay", 0)`, the same with `generation` 0 given, and `idemKey("a", "b", "c", 2, 3)` run; the variants of `("tenant_a", "r_1", "pay", 0, 0)` with `generation` 1, `effectSeq` 1, tenant `tenant_b`, lineage `r_2` and node `mail` run; `lineageOf({ runId: "r_2", lineageId: "r_1" })` runs; and `idemKey` runs with tenant `""` and `"a b"`, lineage `""` and 129 characters, node `"Pay"`, `"1pay"` and `"pay#done"`, `effectSeq` `-1`, `1.5`, `NaN` and `2147483648`, and `generation` `-1`
- **THEN** the first two equal `ik1_677d835c8e07871e5aabcc92745361cea1baa4e358b55523a1862f6cc5132714`; the third equals `ik1_8173a576070efa7d96f078c1eb61c46622685bc8eb75f7343388fc251fc9ef38`, the SHA-256 of the text `["a","b","c",2,3]`; each variant equals `"ik1_"` plus the SHA-256 hex (computed in the test with `node:crypto`) of `JSON.stringify` of its array, and the five differ from the first key and from each other; `lineageOf` returns `"r_1"`; each of the 12 refusals throws `IntentError` with `code` `INTENT_INVALID` and a message without the offending value

### Requirement: effect_intent is a tenant table with narrow privileges
Migration `0340_effect_intent.sql` SHALL create `ursitoare.effect_intent` keyed `(tenant_id, idem_key)` with forced row-level security, a foreign key to the run, CHECK constraints on key, digest, mode, state and the pairing of `done` with `result_ref` and `completed_at`, and grant the app role only `SELECT`, `INSERT` and `UPDATE (state, result_ref, completed_at)`.

#### Scenario: Objects, isolation and privileges
- **WHEN** on `withTestDatabase()` and `seedTwoTenants(db)` the ledger row of version 340, `to_regclass('ursitoare.effect_intent')::text` and `checkTenancyCatalog(db.ownerPool)` are read; runs `r_1` (tenant A) and `r_9` (tenant B) are created; then, each in its own app-pool transaction, tenant A inserts the row of `WRITE()` (state `intent`); inserts rows differing by `idem_key` `'bad'`, `state` `'weird'`, `mode` `'x'`, `args_digest` `'zz'`, state `'done'` with `result_ref` and `completed_at` null, state `'intent'` with both set, `run_id` `'nope'`, and `tenant_id` `'tenant_b'` (run `r_9`); updates `tool`, then `idem_key`, then `state` to `'done'` with a valid `result_ref` and `completed_at`; deletes the row; and tenant B counts rows and updates A's row
- **THEN** the ledger holds version 340 named `effect_intent`, the regclass text is `ursitoare.effect_intent`, the catalogue check returns `[]`; the first insert succeeds; the six rows that break a CHECK reject with `23514`, `run_id` `'nope'` with `23503`, `tenant_b` with `42501`; the `tool` update, the `idem_key` update and the delete reject with `42501`; the valid update has `rowCount` 1; tenant B counts 0 rows and its update has `rowCount` 0; as owner through `withTenantTx(db.ownerPool, T_A, ...)`, A's row is still `done`

### Requirement: recordIntent writes one row per key and keeps the first
`recordIntent(tx, ctx, intent, at)` SHALL insert a row in state `intent` holding the SHA-256 digest of `intent.args` and answer `created: true`, and for an existing key SHALL answer the stored row unchanged with `created: false`, whatever the second call's tool, arguments, mode or time.

#### Scenario: Recording an intent once
- **WHEN** with run `r_1` in tenant A, `recordIntent(tx, T_A, WRITE(), AT)` runs, then `WRITE({ tool: "other.tool@1", args: { vendor_id: "v2" }, mode: "mock" })` at `AT` plus 60 s; `getIntent` runs for `K1`, for an unrecorded valid key and, in a transaction of tenant B with `T_B`, for `K1`; two connections of `db.appPool` call `recordIntent` at once with `WRITE({ idemKey: KEY("mail"), nodeId: "mail", tool: "mail.send@1" })`; and `recordIntent` runs with `idemKey` `"bad"`, `tool` `""`, `nodeId` `"Pay"`, `runId` `""`, `mode` `"x"` (cast), `at` `new Date(NaN)`, `args` `{ n: undefined }` (cast), in a transaction of tenant B with `T_A`, and with `WRITE({ idemKey: KEY("pay", "r_missing"), runId: "r_missing" })`
- **THEN** the first returns `{ created: true, record: { idemKey: K1, runId: "r_1", nodeId: "pay", tool: "erp.create_payment@1", argsDigest: payloadDigest(PAY_ONCE_PAY_ARGS), mode: "live", state: "intent", resultRef: null, createdAt: "2026-11-02T10:00:00.000000Z", completedAt: null } }`; the second returns `created: false` and a record deep-equal to the first; `getIntent` returns that record, `null` and `null`; exactly one of the two concurrent calls has `created: true`; the first six refusals and the tenant mismatch throw `IntentError` `INTENT_INVALID`, the `args` call rejects with `RunDataError` `RUN_DATA_INVALID`, the `r_missing` write rejects with `code` `23503`, and tenant A holds 2 rows (`K1`, `KEY("mail")`)

### Requirement: An intent moves only forward
`completeIntent(tx, ctx, idemKey, result, at)` SHALL store the result through the envelope store and move an `intent` or `unknown` row to `done` with `result_ref` and `completed_at`, SHALL answer a `done` row unchanged; `markIntentUnknown(tx, ctx, idemKey, at)` SHALL move an `intent` row to `unknown` and answer `unknown` and `done` rows unchanged; both SHALL reject an absent key with `INTENT_NOT_FOUND`.

#### Scenario: Completing and marking unknown
- **WHEN** in tenant A, run `r_1`, rows `K1`, `K2` = `KEY("mail")` (tool `mail.send@1`) and `K3` = `KEY("note")` are recorded at `AT`; `completeIntent(K1, PAID, AT + 60 s)` runs, then again with `{ payment_id: "other" }` at `AT + 120 s`, and `envelopeStore.get` reads the `resultRef`; `markIntentUnknown(K1, AT + 180 s)` runs; `markIntentUnknown(K2, AT + 180 s)` runs twice and `completeIntent(K2, PAID, AT + 240 s)` once; both functions run for the unrecorded `KEY("absent")`; `completeIntent(K1, ...)` runs in a transaction of tenant B with `T_B`; `completeIntent` runs with `idemKey` `"bad"` and `completeIntent(K3, { n: undefined } (cast), AT)` runs
- **THEN** the first returns the record with `state` `"done"`, `resultRef` `payloadDigest(PAID)` and `completedAt` `"2026-11-02T10:01:00.000000Z"`, the rest as recorded; the second is deep-equal to it and, read through `withTenantTx(db.ownerPool, T_A, ...)`, `envelope_payload` holds no row for `{ payment_id: "other" }`; `get` returns `data` deep-equal to `PAID`; `markIntentUnknown(K1)` returns the same `done` record; for `K2` both marks return `state` `"unknown"` with `resultRef` and `completedAt` null, then `completeIntent` returns `"done"` with `completedAt` `"2026-11-02T10:04:00.000000Z"`; the unrecorded key gives `INTENT_NOT_FOUND` for both functions, as does tenant B for `K1`; `"bad"` gives `INTENT_INVALID`; the `K3` call rejects with `RunDataError` `RUN_DATA_INVALID` and `K3` stays `intent`

### Requirement: The gate decides invoke, reuse or unknown from the stored state
`createEffectIntents(pool).before(call, ctx)` SHALL answer `invoke` with the key after inserting the intent for a new key, `reuse` with the stored result for a `done` row of the same `mode`, `invoke` with the same key for an `intent` row unless `ctx.unsafeToRetry` is true, and `unknown` for an `unknown` row, for an `intent` row of an unsafe tool (which it SHALL mark `unknown`) for a `done` row whose payload is gone and for a `done` row of another `mode`, in every mode (`live`, `mock`, `stub`) and recording the call's `mode`; `after` SHALL complete the intent and be a no-op when repeated.

#### Scenario: The gate decides from the stored state
- **WHEN** with `intents = createEffectIntents(db.appPool)` and runs `r_1` to `r_6` in tenant A (lineage = run id): `before(CALL, CTX())` runs twice; `after(CALL, CTX(), { output: PAID })` runs twice with the same call and context, the row and the `envelope_payload` rows (read through `withTenantTx(db.ownerPool, T_A, ...)`) being read after each, then `before(CALL, CTX())` runs; `before(CALL, CTX({ runId: "r_2", lineageId: "r_2", unsafeToRetry: true }))` runs three times; `before(CALL, CTX({ runId: "r_3", lineageId: "r_3", mode: "mock" }))` runs; `before(CALL, CTX({ runId: "r_5", lineageId: "r_5", mode: "stub" }))` runs; with `CTX({ runId: "r_6", lineageId: "r_6", mode: "mock" })` `before` runs, then `after` with `{ output: PAID }`, then `before` with `mode` `"live"` and again with `mode` `"mock"`; and with `CTX({ runId: "r_4", lineageId: "r_4" })` `before` runs, then `after` with `{ output: { payment_id: "pay-4", status: "paid" } }`, then the owner deletes that payload from `envelope_payload` through `withTenantTx(db.ownerPool, T_A, ...)`, then `before` runs again
- **THEN** the first two return `{ action: "invoke", idemKey: K1 }` and the table holds one `intent` row for `K1` with `mode` `"live"` and `createdAt` `"2026-11-02T10:00:00.000000Z"`; both `after` calls resolve with `undefined`, the row is `done` with `resultRef` `payloadDigest(PAID)` after the first and deep-equal to that after the second (`completedAt` unchanged), and `envelope_payload` holds one row for that digest after each; the next `before` returns `{ action: "reuse", idemKey: K1, result: { output: PAID } }`; the `r_2` calls return `invoke` with `KEY("pay", "r_2")`, then `{ action: "unknown", idemKey: <that key> }` twice, and its row is `unknown`; the `r_3` call returns `invoke` and its row has `mode` `"mock"`; the `r_5` call returns `invoke` and its row has `mode` `"stub"`; on `r_6` the `mock` call returns `invoke`, the `live` call returns `{ action: "unknown", idemKey: <its key> }` with the row still `done` and `mode` `"mock"`, and the second `mock` call returns `reuse` with `{ output: PAID }`; the last `r_4` call returns `{ action: "unknown", idemKey: <its key> }` and its row is still `done`

#### Scenario: The key follows the lineage, not the run
- **WHEN** in tenant A, runs `r_1`, `r_2` (`lineageId` `"r_1"`, `parentRunId` `"r_1"`) and `r_3`, and in tenant B a run `r_1` exist and `K1` is recorded and completed with `PAID`; `before` runs with `CTX({ runId: "r_2", lineageId: "r_1" })`, with `CTX({ runId: "r_3", lineageId: "r_3" })`, with `CALL` at `effectSeq` 1 and `CTX()`, and with `{ ...CTX(), tenant: T_B }`
- **THEN** the first returns `{ action: "reuse", idemKey: K1, result: { output: PAID } }` and no row has `run_id` `r_2`; the next three return `invoke` with `KEY("pay", "r_3")`, `idemKey("tenant_a", "r_1", "pay", 1)` and `idemKey("tenant_b", "r_1", "pay", 0)` (not `K1`); tenant A holds 3 rows and tenant B 1

### Requirement: The gate inside the interpreter records the intent around the call
Run as the `effects` of `InterpreterDeps`, `createEffectIntents(pool)` SHALL give every block whose effect is not `read` one `effect_intent` row, pass its key to the invoker and to the step record, and a replay of the run from after the paid step SHALL leave the row, the log and the run unchanged.

#### Scenario: The gate inside executeRun, and a replay
- **WHEN** on `withTestDatabase()` and tenant A, `payOnceVersion().flow` is checked with `validateFlow(canonicalizeFlow(flow), loadTestCatalogue())`; `startRun` (mode `live`, `runId` `r_gate_1`, `PAY_ONCE_INPUT`, `durable: null`) and `executeRun` run over a capturing wrapper of `memoryWorkflowOps("r_gate_1")` that records every `runStep` result as `V`, with `payOnceVersion()`, `payOnceCatalogue()`, `effectLogInvoker(file)`, `createEffectIntents(db.appPool)`, `createRunStore(db.appPool)`, `fixedClock("2026-11-02T10:00:00Z")` and `sequentialIds(0)`; then `executeRun` runs again over `memoryWorkflowOps("r_gate_1", V.slice(0, 5))`; `countEffects(file)` and the rows are read after each
- **THEN** the flow check has `ok` true; the first run is `completed` with `outputRef` `payloadDigest({ payment_id: "pay-1" })`; the tenant's `effect_intent` rows are exactly one: `KEY("pay", "r_gate_1")`, node `pay`, tool `erp.create_payment@1`, mode `live`, state `done`, `resultRef` `payloadDigest(PAID)`; the `pay` step row carries that key and the `lookup` row `idemKey` null; the log holds `lookup` with `idemKey` null and `pay` with that key, `countEffects` gives `calls` 2, `effects` 2, `duplicates` 0; the replay executes `["pay#done", "done", "run:finish"]`, returns the completed run, leaves `calls` at 2 and the intent row deep-equal to before

### Requirement: Bad input and a failing database change nothing
The gate SHALL refuse a call or context outside the key's patterns, an invalid `now` and an `after` for an absent intent with an `IntentError`, and SHALL propagate a database failure without writing a row or swallowing the error.

#### Scenario: Refusals and a pool that is down
- **WHEN** with run `r_1` in tenant A, `before` runs with `CALL` at `effectSeq` `-1`, with `nodeId` `"Pay"` and with `CTX({ now: new Date(NaN) })`; `after(CALL, CTX(), { output: PAID })` runs while no intent exists; `before(CALL, CTX())` runs, then `after` with `{ output: { n: undefined } }` (cast); and `before(CALL, CTX())` runs on a `TenantPool` whose `connect` rejects `new Error("down")`
- **THEN** the first three throw `IntentError` `INTENT_INVALID`; the `after` without an intent throws `INTENT_NOT_FOUND`; the bad output rejects with `RunDataError` `RUN_DATA_INVALID`; the last rejects with that same error object (`===`); the table holds one row, for `K1`, in state `intent`

### Requirement: A kill between the intent and the done gives one effect
With `createEffectIntents` as the gate of a durable `live` run of the pay-once flow, a SIGKILL at fault point `after:pay` (the tool returned, the step is not checkpointed, the intent is not `done`) followed by `restart()` SHALL complete the run with the same key sent twice and one effect, or, when `erp.create_payment@1` is `unsafe_to_retry`, fail the run with `INTERPRETER_EFFECT_UNKNOWN` at `pay` after one call.

#### Scenario: Kill after the call, restart, one effect
- **WHEN** the parent of design decision 10 runs `spawnEngine` on `intents-scenario.ts` with `faultPoints` `["after:pay"]` and `runId` `"r_crash_1"`, `effects` `"effects-1.log"`; polls `proc.deaths` to 1 and reads `countEffects` and the intent row; calls `restart()`; waits with `waitForRun(..., ["completed", "failed"], 20000)`; then reads `countEffects`, the log lines, the intent row and `listSteps`
- **THEN** at the death the log holds one `erp.create_payment@1` call and the row `idemKey(<tenantId>, "r_crash_1", "pay", 0)` is `intent`; the run is `completed` with `outputRef` `payloadDigest({ payment_id: "pay-1" })`; `byTool["erp.create_payment@1"]` deep-equals `{ calls: 2, effects: 1, duplicates: 1 }`, the lookup `calls` is 1, and both pay lines carry that key; the row is `done` with `resultRef` `payloadDigest(PAID)`; `listSteps` gives node ids `["lookup", "route", "pay", "done"]`, `seq` 0 to 3, all `completed`, the `pay` row with the key

#### Scenario: Kill after the call of an unsafe tool parks as unknown
- **WHEN** the previous scenario's steps run with `runId` `"r_crash_2"`, `effects` `"effects-2.log"` and `unsafePay` `"true"` (the scenario's catalogue marks `erp.create_payment@1` `unsafe_to_retry`)
- **THEN** the run is `failed` with `error.code` `INTERPRETER_EFFECT_UNKNOWN`, `error.node` `pay` and `terminalNode` `pay`; `byTool["erp.create_payment@1"]` deep-equals `{ calls: 1, effects: 1, duplicates: 0 }`; the intent row is `unknown` with `resultRef` null; the `pay` step row is `failed` and no row exists for node `done`

### Requirement: Completed steps are not repeated across kills
A restart SHALL NOT call a tool whose step was checkpointed: after kills at `after:route` and `after:done`, the read and the payment SHALL each have been called once.

#### Scenario: Two kills, the work already done is not redone
- **WHEN** the parent runs the scenario with `faultPoints` `["after:route", "after:done"]`, `runId` `"r_crash_3"`, `effects` `"effects-3.log"`; polls `proc.deaths` to 1, calls `restart()`, polls `deaths` to 2, calls `restart()` again; waits for the run; then reads `countEffects`, the intent row and `readdirSync(faultMarkerDir(cluster.dataDir))`
- **THEN** the run is `completed` with `outputRef` `payloadDigest({ payment_id: "pay-1" })`; `byTool["erp.lookup_vendor@1"]` and `byTool["erp.create_payment@1"]` each deep-equal `{ calls: 1, effects: 1, duplicates: 0 }`; the intent row is `done`; the marker directory holds exactly the SHA-256 hex names of `after:route` and `after:done`

### Requirement: The runs module exports the intent API
`src/runs/index.ts` SHALL export the functions and the error class of `src/runs/intents`.

#### Scenario: The module exports
- **WHEN** `import * as runs from "src/runs/index.ts"` is read for `idemKey`, `lineageOf`, `recordIntent`, `completeIntent`, `markIntentUnknown`, `getIntent`, `createEffectIntents` and `IntentError`
- **THEN** each of the first seven is a function and `new runs.IntentError("INTENT_NOT_FOUND", "x")` is an `Error` with `code` `INTENT_NOT_FOUND`
