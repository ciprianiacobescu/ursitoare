## MODIFIED Requirements

### Requirement: Authorization is recorded before anything is sent
`recordDecisionOwnTx(pool, ctx, decision, req, extra)` SHALL record one decision in a transaction of its own and answer what `recordDecision` answers (`true` for a new row, `false` for a decision id already recorded at the same `decidedAt`: `src/pdp/log.ts:13,134`). `authorize(call, ctx)` SHALL decide `invoke_tool` with the full context, record the decision with the step's `runId` and `nodeId`, and answer `{ decisionId, permit }` only for an `allow` with `errors` `[]`, where `permit` is the decision's permit, or `null` for a `code` call, whose request has no `egress` member. A `permit` of `null` SHALL exist only for a binding whose call kind is `code`: an `allow` without a permit for an `http` or `mcp` call or a fixture binding SHALL throw `INTERPRETER_TOOL_DENIED` with reason `permit_missing` and `details` `{ reason, decisionId }` after its decision is recorded (the row stays), with no token request and no send. Every other outcome SHALL throw `INTERPRETER_TOOL_DENIED` (message `tool call of "<node>" is not permitted (<reason>)`, `hook` added to `details` for a hook call), write no intent, request no token and send nothing: a `deny` with `errors` `[]` is `policy`, `details` `{ reason, decisionId }`; a `Decision` with non-empty `errors` is a deny whatever its `decision` says, recorded as a `deny` with its `reasons` and `errors` and no permit, and is `policy_error`, `details` `{ reason, decisionId, errorCount }` (`errorCount` the decimal text of `errors.length`, no error text); a rejected `policy.engine.check` is `policy_unavailable`, `details` `{ reason, code }` (the error's own `code` when it is a string matching `^[A-Z][A-Z0-9_]{0,63}$`, else `UNKNOWN`), with no decision, as none exists; a decision that cannot be recorded (`recordDecisionOwnTx` rejects or answers `false`) is `decision_unrecorded`.

### Requirement: A refusal before the policy point records and sends nothing
`authorize` SHALL throw `INTERPRETER_TOOL_DENIED` with message `tool call of "<node>" is not permitted (<reason>)` and `details` `{ reason }` (plus `hook` for a hook call), with no decision and no gateway call, in this order: `tool_unbound`, `tool_unapproved` (a binding of state `pending`; the real directory answers null for such a server, so this is `tool_unbound` there), `surface_drift` (state `drifted`), `adapter_unavailable` (a binding with `call` whose kind has no adapter: `deps.calls.http` for `http`, `deps.calls.mcp` for `mcp`, `deps.code` for `code`), `credential_missing` (never asked for a `code` call, which has no service target), `principal_unknown` (none, or of another tenant; the initiator and the distinct non-null approvers of the `approved` approvals of `ctx.approvals` load on each `authorize`, so a user disabled after the run started is refused at the next call; the approver of a `rejected` approval is not loaded), `args_unconvertible` (`toCedarArgs` not ok), `fingerprint_unavailable` (`loadVersion` answers null, or no node fingerprint); an `http` or `mcp` call whose adapter `build` answers `{ ok: false, reason }` or throws SHALL be `INTERPRETER_TOOL_FAILED` with `{ stage: "request", reason }` (`reason` the adapter's when it matches `^[a-z][a-z0-9_]{0,63}$`, else `adapter_reason`; `adapter_error` for a throw), after `fingerprint_unavailable` and before the check, with no decision and no gateway call; an unrecordable decision SHALL be `decision_unrecorded` after the check; a rejected lookup SHALL be `INTERPRETER_TOOL_FAILED` with `stage` `authorize`. The version and the catalogue load on the first `authorize` of an invoker and are kept (a rejected load is not: design 4).

### Requirement: invoke sends only what was authorised
`invoke(call, ctx)` SHALL throw `INTERPRETER_TOOL_DENIED` with reason `unauthorized` and call nothing when `ctx.authorization` is absent, was not issued by this invoker, or was already given to an `invoke` (an authorization is consumed when `invoke` starts, whether or not the call then succeeds); otherwise, for a binding without `call`, it SHALL request one token for the permit and send the request rebuilt from the authorised binding, target and arguments with the key `ctx.idemKey`, tag `{ tenantId, runId, nodeId, attempt }` (`nodeId` the node's id, or `<node>:<phase>:<label>` for a hook call), and answer `{ output }` for a 2xx response whose body parses as a JSON object (the content type is not read). It SHALL throw `INTERPRETER_TOOL_FAILED` (message `node execution failed`) with `{ stage: "upstream", status }` for any other status (a redirect is not followed), `{ stage: "token" }` for any rejection of `requestToken`, `{ stage: "send" }` for any rejection of `send` whatever its code (`GATEWAY_INVALID`, `GATEWAY_PERMIT_MISMATCH` and `GATEWAY_RESPONSE_TOO_LARGE` included), or `{ stage: "response", reason: "not_json" }` for a 2xx body that is not JSON or not an object; for a binding with `call` of kind `http` or `mcp` it SHALL throw `permit_missing` (`details` `{ reason, decisionId }`) before any token request when the permit is `null`, rebuild the request with the adapter and `ctx.idemKey`, request one token for the permit, send `callRequest(target, rebuilt.request).request` with the same tag, and answer through `adapter.answer`: `{ ok: true, output }` is `{ output }` and `{ ok: false, stage, reason, status }` is `INTERPRETER_TOOL_FAILED` `{ stage, reason }` plus `status` as decimal text when it is an integer; a throwing `answer` `{ stage: "response", reason: "adapter_error" }`, and `token` and `send` failures are as above; for a `code` call it SHALL call `deps.code(call, args, ctx)` with the authorised arguments, request no token and send nothing, pass an `InterpreterError` of the runner through and map any other rejection to `{ stage: "code", reason: "runner" }`; no tool text, header value, token or credential SHALL reach a message, a detail or a log line.

## ADDED Requirements

### Requirement: callRequest builds the one request of an adapter call and its egress
`callRequest(target, request)` SHALL return `{ request, egress }` with `request` `{ method, origin: target.origin, path, headers, body }` and `egress` `{ method, host: new URL(target.origin).host, path, bodyDigest: bodyDigest(body), serviceId: target.serviceId, ttlSeconds: INVOKE_LIMITS.tokenTtlSeconds }`, independent of the headers. `invokeToolRequest` SHALL accept `egress: null` and then build a request with no `egress` member. `toolRequest` on a binding without `http` SHALL throw `RangeError("toolRequest: binding has no http")`, with no network and no decision.
