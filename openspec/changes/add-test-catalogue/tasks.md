Spec: `specs/test-catalogue/spec.md`; signatures and decisions: `design.md`; how the RF-1 variants are made: `derived-flows.md`. Data is copied from `seed/` (read-only and never edited; it stays on the base branch until every M3 change that ports from it has merged, so later units still read it). Each test calls the function inside `assert.doesNotThrow(() => { r = f(x); })` and asserts on `r`, or uses `assert.throws(() => f(x), { code })`, so that red fails by assertion against the scaffold's stub (design.md § Test plan). No test reads a data file itself: it reaches data only through a function of this unit. Test names contain no `.`, `[` or `::`. Every test imports the modules of this unit by their own path (`./document.ts`, `./loader.ts`, ...), the types and functions of U22 from `src/authoring/index.ts`, and nothing from `seed/`.
