# web-flow-graph Specification

## Purpose
The flow graph draws the saved version of a flow as a read-only layered graph in the editor page and on its own page, with an accessible node list and a node detail panel, and the milestone journey proves that an author creates, validates and saves a flow and reads its graph in a browser.

## Requirements

### Requirement: The layout places every node deterministically
`layoutFlow` SHALL turn a flow document into node positions and edges by a fixed algorithm (layers by longest path from the start node, order by id within a layer, fixed geometry), without mutating the document, and refuse documents that are not flows or have more than `MAX_GRAPH_NODES` nodes.

#### Scenario: Layers, order, coordinates and labels of a small flow
- **WHEN** `layoutFlow(S)` runs on `S` (reference.md), on `S` rebuilt with its node keys in reverse order and on a deep-frozen copy of `S`; `layoutFlow(SLASH)` and `layoutFlow(ONE)` run; `GRAPH_GEOMETRY` and `MAX_GRAPH_NODES` are read
- **THEN** the first result deep-equals `{ status: "ok", layout }` with the nodes, edges, width, height, layers and start of reference.md § Layouts "S" (nodes in layout order, each with the other fields that section names); the other two `S` runs deep-equal the first and the frozen one does not throw; `SLASH` and `ONE` equal their sections (several paths: label "a/b, c~d, default"; a lone `/next`: null); `GRAPH_GEOMETRY` is `{ nodeWidth: 160, nodeHeight: 48, gapX: 32, gapY: 56, margin: 16 }` and `MAX_GRAPH_NODES` is 200

#### Scenario: Cycles, unreachable nodes, unknown kinds and missing targets
- **WHEN** `layoutFlow` runs on `CYCLE`, `LOOP`, `ODD`, `NOSTART` and `UNREACH` (reference.md § Test documents)
- **THEN** each result deep-equals its section of reference.md § Layouts: the edge that closes a cycle or a loop is kept with `upward` true and changes no layer; unreachable nodes (all nodes when `start` is absent) sit in the layer after the last reachable one, ordered by id, `reachable` false; their edges (`UNREACH`: b to c inside the last row, c to a into the reached part) are drawn, `upward` true, and take no part in layering; the kind "mystery" and the non-object `z` give `known` false (kind `null` for `z`); a successor naming no node (`ghost`, `toString`) is listed in `missing`, drawn as no edge, never found through the prototype

#### Scenario: Invalid documents, the empty flow and the size bound
- **WHEN** `layoutFlow` gets `null`, `[]`, "x", 42, `{}`, `{ nodes: [] }`, `{ nodes: null }`, `EMPTY`, `Chain200` and `Chain200` with a node `n200`
- **THEN** the first four give `{ status: "invalid", reason: "not_object" }`, the next three `{ status: "invalid", reason: "no_nodes" }`; `EMPTY` and `Chain200` give `{ status: "ok", layout }` with the figures of reference.md; 201 nodes give `{ status: "too_large", count: 201, limit: 200 }` and no layout is computed

### Requirement: The graph has a text equivalent and a state for every case
`graphView` SHALL turn a canonical document into a state, a message and an ordered node list that carries each node's id, kind and successors as text, `nodeDetailRows` SHALL describe one node's fields read-only, and `chooseNode` SHALL accept only ids of the drawn graph.

### Requirement: The graph loads the saved version it shows
The graph SHALL read the latest saved version of a flow, or the document of a given version, through U28's `loadFlow` and `loadVersion`, and turn a malformed id into a not-found error.

#### Scenario: Loading the latest version and a version's document
- **WHEN** `loadLatestGraph(client, "demo-graph", signal)` runs against a recording client that answers `F` then `D` (reference.md § Graph source data), against one that answers `F0`, against one that rejects with `ApiRequestError(404, "NOT_FOUND", "m")`, and with "Bad_Name"
- **THEN** the first calls are exactly `{ path: "/flows/demo-graph", opts: { signal } }` and `{ path: "/flows/demo-graph/versions/" + encodeURIComponent(H), opts: { signal } }` and the result is `{ saved: true, version: 2, canonical: S }`; with `F0` there is the first call only and the result is `{ saved: false, version: null, canonical: null }`; the rejection is passed on unchanged (the same object); "Bad_Name" rejects with `RangeError` and sends nothing

#### Scenario: The panel loads a missing document and says when it fails
- **WHEN** `needsDocument` gets `(V, null)`, `(V, undefined)`, `(V, S)` and `(null, null)`; `loadGraphDocument(client, "demo-graph", H, signal)` runs against a recording client that answers `D`; `GRAPH_LOADING` is read; `settleGraphLoad` gets `Promise.resolve(S)`, `Promise.resolve(null)` and promises rejecting with `ApiRequestError(403, "FORBIDDEN", "m", { details: { decisionId: "d-1" } })`, `new RangeError("x")`, `ApiRequestError(500, "INTERNAL", "m")` and the string "s"; the kit's `errorPanelModel` reads each failure's `error`; `graphView(null, true)` runs

### Requirement: The graph lists hooks, hook routes and flow rules beside the drawing
`hookOverlay(doc, layout)` SHALL read a canonical flow document without changing it and return the `badges` (one per laid-out node with a hook id in `pre` or `post`, in layout order), the `routes` (one per post hook and route that names a laid-out node, without repeats), the `rules` (one per flow rule with a non-empty string id; when the rule's `post` hook declares `routes`, its `post` is `rule.<id> routes <ids joined by ", ">`, so no rule route is hidden) and the `missing` route targets; it SHALL list at most 16 hooks per phase and 16 rules (U41's bounds) and every route (each names a laid-out node), cut an id to 64 characters, and answer four empty lists for a non-flow. `hookSectionView(doc, layout)` SHALL return `null` when `layout` is `null` (no usable layout: unsaved, invalid, empty or over 200 nodes, `FlowGraphView.tsx:22`), without calling `hookOverlay` or reading `doc`; otherwise it SHALL call `hookOverlay(doc, layout)` once and return `{ hooks, routes, rules, missing }`: the `hookBadgeText` of each badge, the `hookRouteText` of each route, the `flowRuleText` of each rule, and `missing` the exact text `Hook routes name nodes that do not exist: <ids joined by ", ">.` when the overlay has missing ids, else `null`. `FlowGraphView` SHALL render the view `hookSectionView(canonical, layout)` returns, mechanically and only when it is not `null`: after the list "Nodes", when `hooks` is not empty an `h3` "Hooks" with a list named "Hooks" (one item per string), when `routes` is not empty an `h3` "Hook routes" with a list named "Hook routes" (one item per string), a paragraph holding `missing` when `missing` is not `null`, and when `rules` is not empty an `h3` "Flow rules" with a list named "Flow rules" (one item per string) followed by one paragraph saying that rules are listed and not drawn; with a layout it SHALL draw each route (`hookOverlay(canonical, layout).routes`) inside the decorative `svg` as a `path` of class `hook-route`, dashed by the rule `.flow-graph-svg path.hook-route { fill: none; stroke: var(--ui-color-accent); stroke-width: 2; stroke-dasharray: 6 4; }` of `hook-overlay.css` (`hookRoutePaths`: key `${from}>${to}:${hook}`, `d` `M x1 y1 L x2 y2` with `x1`, `x2` each node's `x + GRAPH_GEOMETRY.nodeWidth / 2 + 16`, `y1` the bottom of `from`, `y2` the top of `to`; nothing for a route to its own node or to a node not laid out). It SHALL leave `layoutFlow`, `graphView` and the page of a flow without hooks unchanged.
