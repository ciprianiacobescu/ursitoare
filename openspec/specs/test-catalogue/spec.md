# test-catalogue Specification

## Purpose
The shared test world of the authoring and runtime units: the 20 mock blocks with their effects and taint sources, the roles the engine really creates, the RF-1 invoice flow and two variants of it, 45 hook flows, and a typed loader that answers the `Catalogue` interface of `flow-format`. It lets every later test start from one known catalogue instead of its own copy.

## Requirements

### Requirement: The test catalogue document holds the 20 mock blocks
`readCatalogueDocument` SHALL return the seed's catalogue document with its 20 blocks, effects, taint sources and data classes, and the engine's four default roles, and `parseCatalogueDocument` SHALL refuse a malformed document with `CATALOGUE_INVALID` and a pointer to the offending value.

#### Scenario: Twenty blocks keep their effects and taint sources
- **WHEN** the test calls `readCatalogueDocument()` and `readCatalogueDocument(TEST_CATALOGUE_PATH)`
- **THEN** the two results are deep-equal; `Object.keys(doc.blocks)` is, in this order, `invoices.get@1`, `docs.fetch@1`, `mail.read_inbox@1`, `http.get@1`, `erp.lookup_vendor@1`, `crm.find_customer@1`, `orders.get@1`, `kb.search@1`, `calendar.find_slots@1`, `erp.create_payment@1`, `orders.refund@1`, `mail.send@1`, `slack.post_message@1`, `http.post@1`, `crm.create_ticket@1`, `crm.update_ticket@1`, `sheets.append_row@1`, `calendar.create_event@1`, `docs.create@1`, `erp.flag_vendor@1`; the first nine have `effect` `read`, the next two (`erp.create_payment@1`, `orders.refund@1`) `pay`, the next three (`mail.send@1`, `slack.post_message@1`, `http.post@1`) `send` and the last six `write`; `data_class` is `"public"` for `docs.fetch@1`, `http.get@1` and `kb.search@1`, `"private"` for `invoices.get@1`, `mail.read_inbox@1`, `erp.lookup_vendor@1`, `crm.find_customer@1`, `orders.get@1` and `calendar.find_slots@1`, and the other eleven blocks have no `data_class`; the blocks with `untrusted_fields` are exactly `invoices.get@1` (`["raw_text", "vendor_name"]`), `docs.fetch@1` (`["content"]`), `mail.read_inbox@1` (`["messages"]`), `http.get@1` (`["body"]`) and `http.post@1` (`["body"]`); `doc.blocks["mail.send@1"]` is `{ effect: "send", description: "Send an email.", input: { type: "object", properties: { to: { type: "string" }, subject: { type: "string" }, body: { type: "string" } }, required: ["to", "subject", "body"] }, output: { type: "object", properties: { message_id: { type: "string" } }, required: ["message_id"] } }`; `doc.catalogue` is `"ursitoare-blocks"`, `doc.version` is `"0.1.0"`, `doc.model_profiles` is `["default", "fast", "careful"]`, `doc.roles` is `["tenant_admin", "author", "approver", "auditor"]`, `doc.delegate_targets` is `{ n8n: ["archive-invoice", "sync-crm", "generate-report"] }` and `Object.keys(doc.flows_registry)` is `["notify-customer@1"]`

#### Scenario: A malformed document is refused with a code
- **WHEN** the test calls `parseCatalogueDocument` with a small valid document text (`catalogue: "t"`, `version: "0.0.1"`, one block `mail.send@1` with effect `send` and `input` and `output` `{ type: "object" }`, `model_profiles: ["default"]`, `roles: ["approver"]`, `delegate_targets: { n8n: ["w"] }`, `flows_registry: { "notify-customer@1": { inputs: { type: "object" }, outputs: { type: "object" } } }`), and with that text changed in one place each: the text `""`; the text `"{"`; the text `"[]"`; the block's effect set to `"delete"`; the block's key changed to `mail.send`; the block's `input` set to `[]`; `roles` set to `[1]`; `delegate_targets.n8n` set to `"x"`; the registry key changed to `notify-customer`; `blocks` removed; and calls `readCatalogueDocument` with a path inside a directory that does not exist
- **THEN** the valid text returns an object deep-equal to `JSON.parse` of it; each of the ten changed texts throws `CatalogueDataError` with `code` `CATALOGUE_INVALID` and a message starting with, in order, `invalid JSON: `, `invalid JSON: `, `/: `, `/blocks/mail.send@1/effect: `, `/blocks/mail.send: `, `/blocks/mail.send@1/input: `, `/roles/0: `, `/delegate_targets/n8n: `, `/flows_registry/notify-customer: `, `/blocks: ` (after a pointer come `: ` and a reason); the missing path throws `CatalogueDataError` with `code` `CATALOGUE_READ`

### Requirement: The loader answers the Catalogue interface from the document
`loadTestCatalogue` SHALL return a `Catalogue` whose lookups match exact names only, never inherited properties, and return fresh copies, and which knows the four default roles, the model profiles, the `n8n` delegate workflows and the flow `notify-customer` at major 1.

#### Scenario: Block lookups answer exactly
- **WHEN** the test calls `loadTestCatalogue()` and `catalogueFromDocument` of a document with `blocks: {}`; `cat.block("erp.create_payment@1")`, then changes the returned object (`def.effect = "read"` and `def.input = {}`) and calls `cat.block("erp.create_payment@1")` again; and `cat.block` with `"ghost.tool@1"`, `"invoices.get"`, `""`, `"INVOICES.GET@1"`, `"__proto__"`, `"constructor"`, `"toString"` and `"hasOwnProperty"`; and `cat.blockRefs()`; and `block("invoices.get@1")` on the empty-document catalogue
- **THEN** the first and the second answer are deep-equal to `{ effect: "pay", description: "Create a vendor payment. Idempotent on the engine-supplied idempotency key.", input: { type: "object", properties: { vendor_id: { type: "string" }, amount: { type: "number" }, currency: { type: "string" }, reference: { type: "string" } }, required: ["vendor_id", "amount", "currency", "reference"] }, output: { type: "object", properties: { payment_id: { type: "string" }, status: { type: "string" } }, required: ["payment_id", "status"] } }` (the second although the first was changed); the eight other lookups are `undefined`; `blockRefs()` is deep-equal to `Object.keys(readCatalogueDocument().blocks)`; the empty-document catalogue answers `undefined` and its `blockRefs()` is `[]`

#### Scenario: Roles, profiles, delegate targets and flows answer from the document
- **WHEN** the test calls `loadTestCatalogue()` and then `roleNames()`, `role` with `"approver"`, `"finance-approver"`, `"Approver"`, `"__proto__"` and `""`; `modelProfileRefs()`, `modelProfile` with `"fast"` and `"slow"`; `delegateTarget("n8n", w)` for `archive-invoice`, `sync-crm` and `generate-report`, and `("n8n", "ghost")`, `("ghost", "archive-invoice")`, `("__proto__", "archive-invoice")`, `("n8n", "__proto__")`; `flow("notify-customer", 1)`, `flow("notify-customer", 2)`, `flow("notify-customer@1", 1)`, `flow("ghost", 1)`, `flow("notify-customer", 1.5)`, `flow("notify-customer", -1)` and `flow("__proto__", 1)`; and imports `DEFAULT_ROLES` from `src/identity/index.ts`

### Requirement: Flow references are checked against a catalogue
`unresolvedReferences` SHALL list every block, role, model profile, delegate target and flow a flow names that the catalogue does not know, and `canReach` SHALL tell whether a node can be reached from the start without passing through a given node.

#### Scenario: Unknown names are listed, known names are not
- **WHEN** the test calls `unresolvedReferences(flow, cat)` with `cat = loadTestCatalogue()` and a flow whose nodes are: a `block` node with `uses: "ghost.do@1"`; a `block` node with `uses: "mail.send@1"` and `post: [{ id: "h", kind: "block", uses: "ghost.hook@1", with: {} }]`; a `human.approval` with `assignee_role: "finance-approver"`; an `llm.extract` with `model_profile: "slow"`; a `delegate` with `target: "n8n"` and `workflow: "ghost"`; a `subflow` with `flow: "notify-customer@2"`; a `foreach` with `uses: "ghost.each@1"` and `subflow: "notify-customer"`; an `agent` with `tools: ["mail.send@1", "ghost.tool@1"]`; and `hooks: [{ id: "r", match: {}, pre: { id: "r", kind: "block", uses: "ghost.rule@1", with: {} } }]`; then with a flow naming only `mail.send@1`, role `approver`, model profile `default`, `n8n` workflow `archive-invoice` and subflow `notify-customer@1`; and with `null`, `"x"`, `{}` and `{ nodes: 5 }`
- **THEN** the first result is exactly `["block:ghost.do@1", "block:ghost.each@1", "block:ghost.hook@1", "block:ghost.rule@1", "block:ghost.tool@1", "delegate:n8n/ghost", "flow:notify-customer", "flow:notify-customer@2", "model_profile:slow", "role:finance-approver"]`; the other five results are `[]`

#### Scenario: Reachability follows successors and avoids a node
- **WHEN** the test calls `canReach` on a flow with `start: "a"`, node `a` a `switch` with `cases: { p: "b", q: "c" }` and `default: "c"`, node `b` a `block` with `next: "c"`, and `c` and `d` `end` nodes: `canReach(f, "c")`, `canReach(f, "c", "b")`, `canReach(f, "b", "b")`, `canReach(f, "d")`, `canReach(f, "a")`, `canReach(f, "c", "a")`, `canReach(f, "ghost")`, `canReach(f, "c", "ghost")`; on a cycle `a -> b -> a` (both `block` nodes) `canReach(cycle, "z")`; and `canReach(null, "a")`
- **THEN** the results are `true`, `true`, `false`, `false`, `true`, `false`, `false`, `true`, `false`, `false`; the cycle call terminates

### Requirement: The RF-1 flows are shipped and loaded by name
`loadTestFlow` SHALL return the flows `rf-1-invoice-intake`, `rf-1-core` and `rf-1-core-approval` as plain documents, with the role `approver`, no delegate in the two variants, and `approval` on every path to `pay` in `rf-1-core-approval`.

#### Scenario: The three RF-1 flows have the shipped shape
- **WHEN** the test calls `loadTestFlow` with `"rf-1-invoice-intake"`, `"rf-1-core"` and `"rf-1-core-approval"` and reads `TEST_FLOW_NAMES`
- **THEN** `TEST_FLOW_NAMES` is those three names in that order; for all three `ursitoare` is `"0.1"`, `version` is `"1.0.0"`, `start` is `"fetch_invoice"` and `nodes.pay.uses` is `"erp.create_payment@1"`; the `flow` values are `"invoice-intake"`, `"rf-1-core"` and `"rf-1-core-approval"`; the sorted node ids are `approval, archive, classify, done, extract, fetch_invoice, lookup_vendor, normalize, notify_rejection, pay, rejected` for the first, the same without `approval` and `archive` for `rf-1-core`, and the same without `archive` for `rf-1-core-approval`; `nodes.pay.next` is `"archive"` in the first and `"done"` in the other two; `nodes.classify.cases` is `{ auto_approve: "pay", needs_review: "approval", reject: "notify_rejection" }`, `{ auto_approve: "pay", needs_review: "notify_rejection", reject: "notify_rejection" }` and `{ auto_approve: "approval", needs_review: "approval", reject: "notify_rejection" }` respectively; `nodes.approval.assignee_role` is `"approver"` in the first and third; `nodes.archive` of the first is a `delegate` with `target` `"n8n"` and `workflow` `"archive-invoice"`; no node of the two variants has kind `delegate`

#### Scenario: Only the approval variant forces approval before pay
- **WHEN** the test calls `canReach(flow, "pay")` and `canReach(flow, "pay", "approval")` for each of the three flows
- **THEN** the first call is `true` for all three; the second is `true` for `rf-1-invoice-intake` and `rf-1-core`, and `false` for `rf-1-core-approval`

#### Scenario: Flow text is parsed or refused, and only shipped names are read
- **WHEN** the test calls `parseCatalogueFlow` with `("ursitoare: \"0.1\"\nflow: t\n", "t")`, `("a: [\n", "bad")`, `("- 1\n", "list")` and `("", "empty")`; and `testFlowPath`, `readTestFlowText` and `loadTestFlow` with `"ghost"`, `""`, `"rf-1-core.yaml"`, `"../flows/rf-1-core"` and `"__proto__"`; and `testFlowPath("rf-1-core")` and `readTestFlowText("rf-1-core")`
- **THEN** the first call returns `{ ursitoare: "0.1", flow: "t" }`; the other three throw `CatalogueDataError` with `code` `CATALOGUE_FLOW_PARSE` and a message starting with `bad: FORMAT_YAML_SYNTAX: `, `list: ` and `empty: `; each of the fifteen name calls throws `CatalogueDataError` with `code` `CATALOGUE_UNKNOWN_FLOW`; `testFlowPath("rf-1-core")` is absolute and ends with `/test/support/catalogue/flows/rf-1-core.yaml`, and the text starts with `ursitoare: "0.1"`

#### Scenario: Content hashes are stable and distinct
- **WHEN** the test calls `contentHash(loadTestFlow(name))` twice for each of the three names, `contentHash` of `parseFlowText(JSON.stringify(loadTestFlow("rf-1-core")), "json")`'s `doc`, and `isContentHash` on each hash
- **THEN** the two hashes of each name are equal; the three hashes are pairwise different; the JSON-surface hash equals the YAML-surface hash of `rf-1-core`; `isContentHash` is `true` for each

### Requirement: The hook flows are shipped and loaded by name
The hook-flow module SHALL list, locate, title and load the 45 hook flows by name, and SHALL refuse any other name.

- **WHEN** the test calls `hookFlowNames("scenario")`, `hookFlowNames("static")`, `hookFlowNames()`; `hookFlowTitle` for `n-block`, `s09-onion` and `x3-gate-bypass`; `readHookFlowText("f-eff")`; `hookFlowPath("n-block")` and `hookFlowPath("f-eff")`; `existsSync(hookFlowPath(name))` for every listed name; and `loadHookFlow("f-eff")`
- **THEN** the scenario list is `c2-effect-post-hook, f-eff, f-ret, f-ret-exhausted, m-h0, m-h1, m-h2, s02-pre-mutate, s03-post-mutate, s04-pre-skip, s06-next-redirect, s07-next-block-hook, s08-from-logic, s09-onion, s10-park-hooks, s10b-timeout-post, s11-end-pre, s12a-fail, s12b-block-onerror, s13-undeclared-route, s14-unsafe-redirect, s14c-cycle, s15-guard, s15-guard-redirect, s16a-raise, s16b-lower, s17-taint, s18a-skip-human, s18b-rewrite-decision, s18c-skip-effect, s18d-routes-on-human, s19-block-hook-pep, x1a-retry-pay, x1b-retry-raise, x2-skip-taint, x3-gate-bypass` (36 names); the static list is `n-block, n-dominance-hook, n-no-match, n-retry-scope, n-retry-scope-human, n-route-self, n-route-target, n-schema, n-schema-routes-pre`; the full list is the two lists together sorted by code unit (45 names); the titles are `H_BLOCK: missing required input`, `S09 flow selectors and onion order (A=rule_a, B=rule_b)` and `X3: a declared route can skip a human gate upstream of it`; the text of `f-eff` starts with `# generated by tests/gen-flows.mjs: C6 retry on an effect node` followed by a line feed; the paths end with `/test/support/hook-flows/flows/static/n-block.yaml` and `/test/support/hook-flows/flows/f-eff.yaml`; every listed file exists; `loadHookFlow("f-eff")` has `flow` `"f-eff"`, `ursitoare` `"0.2-draft"`, `start` `"send"`, sorted node ids `["done", "send"]` and `nodes.send.post[0].allow_effect_retry` `true`

#### Scenario: Unknown hook-flow names are refused
- **WHEN** the test calls `hookFlowPath`, `readHookFlowText`, `hookFlowTitle` and `loadHookFlow` with `""`, `"ghost"`, `"n-block.yaml"`, `"static/n-block"`, `"../index"`, `"__proto__"` and `"F-EFF"`

### Requirement: Every shipped flow resolves against the test catalogue
Every flow of `TEST_FLOW_NAMES` and of `hookFlowNames()` SHALL parse and name only blocks, roles, delegate targets and model profiles that `loadTestCatalogue()` knows.

#### Scenario: All 48 shipped flows resolve
- **WHEN** the test loads each name of `TEST_FLOW_NAMES` with `loadTestFlow` and each name of `hookFlowNames()` with `loadHookFlow`, and calls `unresolvedReferences(flow, loadTestCatalogue())` on each
- **THEN** every result is `[]`; for each hook flow `flow` equals its name; every node of kind `human.approval` in all 48 flows has `assignee_role` `"approver"`; and the hook flows that have no `human.approval` node are exactly `f-eff`, `f-ret` and `f-ret-exhausted`
