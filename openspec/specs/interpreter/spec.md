# interpreter Specification

## Purpose
The interpreter walks a stored flow version as one durable run: references over recorded outputs, tools only through an invoker and an effect gate, one numbered step row per node visit, on DBOS or in memory.

## Requirements

### Requirement: Node runtimes are registered once per kind
`registerNodeRuntime` SHALL register one runtime per `NodeKind` and refuse a second one or one without `execute`; `block`, `code`, `end`, `switch` and `wait` SHALL be built in.

#### Scenario: Built-in kinds and registration rules
- **WHEN** `nodeRuntimeFor` gets each of the 14 `NODE_KINDS` and `"constructor"`; then, with `RT = { execute: async () => OUTCOME }` (any outcome), `registerNodeRuntime` gets `("block", RT)`, `("human.form", {})`, `("nope", RT)`, `("human.form", RT)` and `("human.form", RT)` again
- **THEN** `SUPPORTED_KINDS` deep-equals `["block", "code", "end", "switch", "wait"]`; the lookups return a runtime with a function `execute` for exactly those five kinds, `undefined` otherwise, and the runtime for `code` is `codeRuntime`; the calls throw `InterpreterError` with `code` and `details.kind`: `NODE_RUNTIME_DUPLICATE` `block`, `NODE_RUNTIME_INVALID` `human.form` and `nope`; the fourth returns, then `nodeRuntimeFor("human.form") === RT`; the fifth throws `NODE_RUNTIME_DUPLICATE`

### Requirement: Values resolve over recorded outputs
`resolveValue` SHALL replace each `${{ }}` reference by the value it names in the run inputs and recorded node results (type kept for a string that is one reference, stringified inside a longer string) and refuse an unresolved one with `INTERPRETER_REF_UNRESOLVED`.

#### Scenario: References, templates and unresolved paths
- **WHEN** with `SCOPE` (test-plan.md) `resolveValue` gets `"${{ inputs.invoice.total }}"`, `"${{ nodes.lookup.output.nested }}"` (then mutated), `"Pay ${{ inputs.invoice.id }}: ${{ inputs.invoice.total }} ${{ nodes.lookup.output.nested }}"`, `"${{ nodes.route.outcome }}"`, `{ a: ["${{ inputs.none }}", "plain", 7] }` and `JSON.parse('{"__proto__":"${{ inputs.invoice.id }}","ok":1}')`; each alone, the seven `UNRESOLVED` strings (test-plan.md)
- **THEN** the results are `120`, `{ k: 1 }` (scope copy unchanged), `Pay inv-1: 120 {"k":1}`, `active`, `{ a: [null, "plain", 7] }` and an object with own keys `["__proto__", "ok"]`, `__proto__` `"inv-1"` and prototype `Object.prototype`; the seven refusals throw `InterpreterError` `INTERPRETER_REF_UNRESOLVED`; the first has `details.ref` `inputs.missing`; the `id.length` one lacks `inv-1`

### Requirement: Switch and end nodes finish without a tool
The `switch` runtime SHALL answer the successor of the case whose own key equals `on` (a number or boolean through `String`, any other value matches none), else `default`, with outcome the key or `default`; the `end` runtime SHALL answer `end.status` and the resolved `output` (`null` when absent).

#### Scenario: Switch cases and end outputs through the conformance kit
- **WHEN** `runConformance("switch", nodeRuntimeFor("switch"), cases)` gets the node `SW` (test-plan.md) with `inputs.k` `2`, `"gold"`, `true`, `null`, `{ a: 1 }`, `"constructor"` and with `inputs` `{}`; and `runConformance("end", nodeRuntimeFor("end"), cases)` gets `END_OUT` with `k` `"gold"`, `{ kind: "end", status: "completed" }` and `{ kind: "end", status: "failed" }`
- **THEN** every result has `ok: true` for these expectations: switch `{ output: null, outcome: "2", next: "two", end: null }`, `outcome: "gold"` with `next: "g"`, `outcome: "true"` with `next: "yes"`, `outcome: "default"` with `next: "dflt"` for the next three, error `INTERPRETER_REF_UNRESOLVED` for empty `inputs`; end `{ output: { id: "gold" }, outcome: null, next: null, end: { status: "completed" } }`, the same with `output: null`, and `end: { status: "failed" }` with `output: null`

### Requirement: A block calls its tool through the invoker
The `block` runtime SHALL check the resolved `with` against the block's `input` schema, call `ToolInvoker.invoke` once with `{ tool, args, nodeId, effectSeq: 0 }` and the `StepContext`, check the result against `output`, and map an invoker rejection to `INTERPRETER_TOOL_FAILED` without its message.

#### Scenario: A read block, with schema and tool failures
- **WHEN** the `block` runtime executes node `lookup` (`uses` `erp.lookup_vendor@1`, `with` `{ vendor_name: "${{ inputs.vendor }}" }`, `next` `route`) with `CTX("lookup")`, `inputs.vendor` `"Acme"`, a recording invoker answering `{ output: LOOKUP_OK }` and a recording gate; then, each alone, `inputs.vendor` `5`, an invoker answering `{ output: { status: "active" } }`, one rejecting `new Error("db password=hunter2")`, and `services.block` answering `undefined`
- **THEN** the first returns `{ output: LOOKUP_OK, outcome: null, next: "route", end: null }`, `executed` is `["lookup"]`, the invoker got one call, `deepEqual` to `{ call: { tool: "erp.lookup_vendor@1", args: { vendor_name: "Acme" }, nodeId: "lookup", effectSeq: 0 }, ctx: CTX("lookup") }`, the gate was not called; the others reject with `node` `lookup` and `INTERPRETER_INPUT_INVALID` (no invoker call), `INTERPRETER_OUTPUT_INVALID`, `INTERPRETER_TOOL_FAILED` (message lacking `hunter2`), `INTERPRETER_VERSION_NOT_RUNNABLE`

### Requirement: An effectful block runs inside the effect gate in every mode
For a block whose effect is not `read`, the `block` runtime SHALL call `EffectGate.before` in the step named after the node, invoke the tool only on the decision `invoke`, call `EffectGate.after` in the step `<node>#done`, and fail with `INTERPRETER_EFFECT_UNKNOWN` on `unknown`.

#### Scenario: Gate order, decisions and failures
- **WHEN** node `pay` (`uses` `erp.create_payment@1`, `next` `done`, resolved args `PAY_ARGS`) runs with context `CTX` on `ops` that tag each log entry with the running step's name, with a logging gate and invoker: in mode `mock` with the decision `{ action: "invoke", idemKey: "ik_1" }` and output `PAID`; in mode `live` with `{ action: "reuse", idemKey: "ik_1", result: { output: REUSED } }`; with `{ action: "unknown", idemKey: "ik_1" }`; with `NO_EFFECT_GATE`; and, with `invoke`, a gate whose `before` rejects `E_GATE`, one whose `after` rejects `E_GATE`, an invoker answering `{ output: { payment_id: "p" } }` and one rejecting `new Error("boom")`
- **THEN** with `CALL` the `ToolCall` of `pay`: the first logs exactly `pay: before(CALL, CTX)`, `pay: invoke(CALL, CTX + idemKey ik_1)`, `pay#done: after(CALL, CTX + idemKey ik_1, { output: PAID })`, returns `PAID` with `next: "done"`, `executed` `["pay", "pay#done"]`; the second logs `before`, `after` with the reused result, no `invoke`, returns `pay-0`; the third rejects `INTERPRETER_EFFECT_UNKNOWN` (`node` `pay`), logs only `before`, `executed` `["pay"]`; the fourth succeeds with `idemKey: null` in the invoker's context; the invalid output logs `after`, then rejects `INTERPRETER_OUTPUT_INVALID`; the rejecting `before` gives `INTERPRETER_TOOL_FAILED` (no invoke, `executed` `["pay"]`), the rejecting `after` and the rejecting invoker the same code (the invoker case with no `after`); no message holds `gate secret`

### Requirement: A wait sleeps in live mode and is skipped in mock mode
The `wait` runtime SHALL sleep through `WorkflowOps.sleep` in chunks of at most 86,400,000 ms in modes `live` and `stub`, and in mode `mock` not sleep and answer outcome `skipped`; `durationMs` SHALL convert weeks, days, hours, minutes and seconds (decimals only on seconds) to milliseconds and refuse other text, a duration over 366 days (31,622,400,000 ms) and any non-finite result with `INTERPRETER_INPUT_INVALID`.

#### Scenario: Sleeping, skipping and parsing durations
- **WHEN** `durationMs` gets `PT0S`, `PT1.5S`, `PT90M`, `P1W`, `P1DT2H3M4S`, `P366D` and, each alone, the nine `BAD_DURATIONS` (test-plan.md, the last three too large); the `wait` runtime (node id `w`, `next` `after`) executes `P2DT1H` in mode `live`, `PT90M` in `mock` and in `stub`, `PT0S` in `live`, and `P1Y` in `mock`, each on fresh `memoryWorkflowOps`

### Requirement: A run records one numbered row per node visit
`executeRun` SHALL move a `queued` run to `running`, visit nodes from `start` writing one `step_execution` row per node visit attempt (one attempt unless a post-hook retries) with `seq` 0, 1, 2 in row order, and finish the run at an `end` node, in steps `run:load`, `run:start`, the steps of each node (its id, `<id>#done`, `<id>#wake`, a hook step `<node>:<phase>:<label>` and, for an effectful block hook, `<node>:<phase>:<label>#done`, and `:r<attempt>` appended for a retried attempt) and `run:finish`; a replay SHALL reuse the numbers and call nothing already recorded.

#### Scenario: A run walks block, switch, block and end
- **WHEN** `startRun` (with `durable: null`, mode `mock`, `runId` `r_1`) and then `executeRun` on tagged `memoryWorkflowOps("r_1")` run flow `pay-once` (test-plan.md) with an invoker answering `LOOKUP_OK` then `PAID`, a gate answering `{ action: "invoke", idemKey: "ik_pay_1" }`, `erp.create_payment@1` `unsafe_to_retry: true`
- **THEN** the result is the stored run: `completed`, `terminalNode` `done`, `outputRef` `payloadDigest({ payment_id: "pay-1" })`, `startedAt` and `endedAt` `2026-11-02T10:00:00.000000Z`; `executed` is `["run:load", "run:start", "lookup", "route", "pay", "pay#done", "done", "run:finish"]`; `invokerFor` got `("mock", run)` once; `listSteps` gives the four rows of `PAY_ROWS`; the invoker's contexts are `CTX("lookup")` and `CTX("pay")` with `effect` `pay`, `unsafeToRetry` true, `idemKey` `ik_pay_1`

- **WHEN** the previous run captured every `runStep` result as `V` (eight values); `executeRun` runs again on the same store over `memoryWorkflowOps("r_1", V.slice(0, 4))` with fresh recording fakes, and over `memoryWorkflowOps("r_1", V)`
- **THEN** the four-value replay has `executed` `["pay", "pay#done", "done", "run:finish"]`, one fresh invoker call (`pay`), `listSteps` `deepEqual` to `PAY_ROWS` (`seq` 0 to 3) and returns the completed run; the eight-value replay executes nothing, calls neither invoker nor gate, keeps the rows and returns the recorded final run

### Requirement: A failing run ends failed with a RunError and leaks nothing
`executeRun` SHALL end a run `failed` with `error` `{ code, message, node }` when a node fails, an invoker is missing or a node is visited twice, store a failed visit as a `failed` row, keep raw tool errors out of every stored value, run nothing for a terminal run, and let any other `RunStore` rejection propagate unchanged, leaving the run row as last stored and retrying nothing.

### Requirement: A run starts only by registry id and hash
`startRun` SHALL load the version through `loadVersion`, refuse a missing, `draft`, unsupported-kind, unknown-block or ill-typed-input start, or a load rejection, without storing a run, store a `queued` run owned by the version's team, enqueue `ursitoare.run` under `workflowIdOf(tenantId, runId)` (`tenantId:runId`), and answer the stored run for a known id.

### Requirement: An invoker that authorizes is asked before the intent
When `services.invoker.authorize` exists, `blockRuntime` SHALL call it inside the node's first step, after `prepare()` and before `effects.before`, with `{ ...ctx, taint: services.inputTaint?.() ?? ctx.taint }`, call `invoke` with `authorization` set to its answer, return the step value `{ output, decisionId }` (read) or `{ output, idemKey, decisionId }` (effect), and call `services.decided?.(decisionId)` after the step returned, fresh or replayed; a throw of `authorize` SHALL end the step before `effects.before` and `invoke`. Without `authorize` the calls, contexts and step values SHALL be exactly M5's and `decided` SHALL not be called. `INTERPRETER_TOOL_DENIED` SHALL be in `InterpreterErrorCode` and in `INTERPRETER_ERROR_CODES` (the list `toInterpreterError` accepts, `errors.ts:19-42`), so a plain object carrying it is an `InterpreterError`; a replayed failed step stays `dbos_failed` until PR #84 merges (M5 D21), and no row here replays one.

#### Scenario: Order, values, denial, replay and the unchanged M5 path

### Requirement: Rows carry the decision id
`visitNode` SHALL give `NodeServices.inputTaint` (the effective input taint of the attempt so far, the labels its final row would carry) and `decided`, write `policyDecisionId` on the attempt's final row from `decided` (the `started` row and an attempt without a node authorization carry `null`), and, when nothing was `decided` for the attempt, use the `details.decisionId` of its error unless the error has `details.hook` (a denied node call); a hook's decision SHALL not be passed to `decided` and never becomes the row's id. A replay over recorded step values SHALL write the same ids; a mock run SHALL write `null`.
